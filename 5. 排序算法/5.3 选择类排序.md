## 📌 选择类排序核心总特性🧩

选择排序家族拥有统一的底层核心逻辑：**每一轮从无序区筛选出目标最值（升序场景选取最小值），将最值固定到有序区边界，无序区同步收缩、有序区持续扩张，最多执行n−1轮即可完成全局排序**。

该家族分为两大实现分支：

1. **简单选择排序**：暴力遍历无序区完成最值检索，实现极简但时间效率上限偏低
2. **堆排序**：借助完全二叉树堆结构优化最值查找逻辑，将整体复杂度优化至 $O(nlogn)$，是工业场景常用的原地高性能排序算法

## 一、基础入门：简单选择排序🔍

### 1. 逐轮执行完整逻辑📊

>📍简单选择排序逐趟执行演示图

![选择类排序 6.png](<../pict/选择类排序 6.png>)

1. 初始状态：整个数组全部为无序区，有序区长度为 $0$
2. 单轮固定操作流程：
    
    ① 遍历当前无序区所有元素，记录区间内最小值的下标`min_idx`
    
    ② 将无序区起点元素和最小值元素交换，最小值进入有序区末尾锁定最终位置
    
    ③ 无序区左边界向右扩张 $1$ 位，重复执行 $n−1$ 轮，所有元素都会完成定位

### 2. 复杂度与稳定性参数说明⚠️

```cpp
// 选择排序：最好/最坏/平均时间复杂度都是O(n^2)，就地排序，不稳定
```

- ⏱️时间复杂度：无论数组初始有序程度如何，每一轮都必须完整遍历无序区查找最小值，**最好、最坏、平均时间复杂度恒为 $O(n^2)$**
- 📦空间复杂度：$O(1)$，仅使用常数级临时变量，属于原地排序
- ⚖️稳定性：不稳定，跨区间交换操作会打乱相等元素的原始先后顺序，示例演示中 $4$ 与 $4∗$ 的相对位置就发生了颠倒

```cpp
// ---------- 第三类：选择类排序 ----------
void SelectionSort::Sort() {
    int n = static_cast<int>(data_.size());
    // 外层循环：共n-1轮，i为已排序区间末尾，每轮确定一个最小值的最终位置
    for (int i = 0; i < n - 1; ++i) {
        int min_idx = i; // 初始化无序区最小值下标为区间起点
        // 内层循环：遍历无序区剩余元素，更新最小值下标
        for (int j = i + 1; j < n; ++j) {
            if (data_[min_idx] > data_[j]) min_idx = j;
        }
        std::swap(data_[i], data_[min_idx]); // 将最小值交换到已排序区末尾
        PrintStep(i + 1); // 打印第i+1轮排序结果
    }
}
```

### 4. 和堆排序的底层逻辑统一对照💡

二者本质都属于选择排序体系，仅「找最大值的实现方式」存在区别：

- 简单选择排序：暴力遍历整个无序区找最大值，单次查找开销 $O(n)$
- 堆排序：依托大顶堆特性，堆顶天然就是最大值，单次获取仅 $O(1)$，交换后仅需 $O(logn)$ 开销就能恢复堆结构

## 二、进阶高性能选择排序：堆排序🌳

### 前置铺垫：堆的基础概念📚

#### 1. 堆的严格定义

堆是依托**完全二叉树**存储的数组结构，分为两类：

- 🏔️大顶堆（大根堆）：父节点的值大于两个子节点的值，堆顶为整棵树的全局最大值
- 🏕️小顶堆（小根堆）：父节点的值小于两个子节点的值，堆顶为整棵树的全局最小值

### （一）两种建堆方式原理 + 时间复杂度严谨推导🧮

#### 1. 方案一：原地向下调整建堆（复杂度 $O(n)$ 推导）

**实现逻辑**：先把全部数据存入数组构成完全二叉树，从最下层的小子树开始向上调整，最后调整根节点所在的整棵树；从倒数第二层的非叶子节点开始，依次对每个非叶子节点执行下沉操作：父节点和两个孩子的最大值对比，若父节点更小就和最大孩子交换，持续下沉直到满足大顶堆性质。

**复杂度数学推导**：

高度为h的完全二叉树，第k层最多有 $2k−1$ 个节点，每个节点最多向下下沉 $h−k$ 层。总调整操作次数为 $\sum_{k=1}^{h} 2^{k-1}(h-k)$，级数化简后总和趋近于 $2^h=n$，因此整体渐进时间复杂度为线性 $O(n)$，效率极高。

#### 2. 方案二：边插入边向上调整建堆（复杂度 $O(nlogn)$ 推导）

**实现逻辑**：在已经建好的合法大顶堆末尾逐个插入新结点，新结点和其父节点对比，若大于父节点就交换位置，循环向上上浮直到不满足交换条件为止。

**复杂度数学推导**：

一共需要插入 $n−1$ 个元素，第 $i$ 个元素插入时，最坏上浮层数为 $⌊log2​i⌋$ ，总上浮操作次数为$\sum_{i=1}^{n-1} \log_2i \approx n\log_2n$，因此整体渐进时间复杂度为 $O(nlogn)$。

#### 3. 关键统一结论：排序阶段两种建堆前置方案的时间复杂度完全一致✅

无论初始采用 $O(n)$ 的向下建堆、还是 $O(nlogn)$ 的向上建堆，**后续排序循环的时间复杂度严格一致，均为 $O(nlogn)$**：

排序阶段一共执行 $n−1$ 轮，每一轮交换堆顶后堆规模减 $1$，单次向下调整最坏开销为 $O(logk)$（$k$为当前堆的有效大小），全轮总调整次数 $\sum_{k=2}^{n}\log_2k \approx ​n\log n$。两种方案的差距仅存在于初始建堆的前置开销，排序主流程的复杂度完全相同。

**代码实现细节补充**：排序循环中，每一轮把堆顶最大值交换到数组末尾，等价于**每次删除堆的最后一个叶子结点🍃**，堆的有效规模同步缩小，仅需要对前端剩余元素重新调整堆结构，完美复用堆的固有特性。

>**关键说明：**堆排序排序阶段堆顶下沉调整、边插入建堆堆尾上浮调整，二者遍历层数、参与调整的节点总数完全相等，覆盖除根节点以外所有节点。

### （二）堆排序完整执行分步拆解📝

![选择类排序 4.png](<../pict/选择类排序 4.png>)

1. 初始建堆：将整个无序数组处理为合法大顶堆，堆顶存放全局最大值
2. $n−1$ 轮排序循环：
    
    ① 堆顶（无序区当前最大值）和无序区末尾元素交换，末尾位置锁定进入有序区
    
    ② 对前端剩余无序元素，从根节点向下下沉调整，重新恢复大顶堆性质
    
    ③ 无序区右边界左移收缩，有序区扩张，循环执行至全部元素有序

### （三）堆排序复杂度与稳定性总结📊

```cpp
// 堆排序：时间复杂度O(nlogn) 就地排序 不稳定
```

- ⏱️时间复杂度：初始建堆最优 $O(n)$，排序循环稳定 $O(nlogn)$，**最好 / 最坏 / 平均整体复杂度均为 $O(nlogn)$**
- 📦空间复杂度：$O(1)$，全程原地操作，仅使用常数临时变量
- ⚖️稳定性：不稳定，父子节点跨位置交换会打乱相等元素的原始先后顺序

### （四）C++ 完整堆排序源码（仅微调注释，源码完全保留）💻

```cpp
// ---------- 第三类：选择类排序 ----------
void HeapSort::SetAdjustType(AdjustType type) noexcept {
    adjust_type_ = type;
}

void HeapSort::DownAdjust(int cur, int heap_size) noexcept {
    // 左孩子：2*cur+1，右孩子：2*cur+2，最大合法下标=heap_size-1
    while (2 * cur + 1 < heap_size) {
        int next = 2 * cur + 1; // 先默认指向左孩子
        // 若右孩子存在且数值更大，切换到右孩子作为待交换对象
        if (next + 1 < heap_size && data_[next + 1] > data_[next]) {
            next++;
        }
        // 父节点小于最大孩子节点，执行交换并向下下沉
        if (data_[cur] < data_[next]) {
            std::swap(data_[cur], data_[next]);
            cur = next;
        }
        else {
            break; // 已经满足大顶堆性质，终止下沉循环
        }
    }
}

void HeapSort::UpAdjust(int cur) noexcept {
    // 0下标规则：父节点下标 = (cur-1)/2
    while (cur > 0) {
        int parent = (cur - 1) / 2;
        // 当前节点大于父节点，执行交换并向上上浮
        if (data_[cur] > data_[parent]) {
            std::swap(data_[cur], data_[parent]);
            cur = parent;
        }
        else {
            break; // 已经满足大顶堆性质，终止上浮循环
        }
    }
}

void HeapSort::Sort() {
    int n = static_cast<int>(data_.size());

    // 1. 构建初始大顶堆
    if (adjust_type_ == AdjustType::Downward) {
        // 向下调整建堆：从最后一个非叶子节点向前遍历，逐个执行下沉操作
        for (int i = n / 2 - 1; i >= 0; --i) {
            DownAdjust(i, n);
        }
    }
    else {
        // 向上调整建堆：从第二个元素向后遍历，逐个上浮（等价于逐个向堆插入元素）
        for (int i = 1; i < n; ++i) {
            UpAdjust(i);
        }
    }

    // 2. 逐轮排序：每轮选出当前堆顶最大值，交换到无序区末尾，再调整恢复堆性质
    // 循环变量i：当前无序区的末尾下标，同时也是本轮最大值需要放置的目标位置
    // 0下标体系说明：DownAdjust第二参数为堆有效元素总数，合法下标范围为0 ~ heap_size-1
    // 传入i作为堆大小，天然对应下标0~i-1，自动排除已经放到i位置的有序元素
    for (int i = n - 1; i > 0; --i) {
        std::swap(data_[0], data_[i]); // 堆顶当前最大值交换到无序区末尾i位置，该位置进入有序区
        DownAdjust(0, i);              // 剩余堆有效大小为i（下标0~i-1），从根节点下沉恢复大顶堆
        PrintStep(n - i);              // 打印第n-i轮排序结果
    }
}
```

### （五）堆的拓展工业应用场景🚀

1. 🛤️图论算法优化：Prim 最小生成树、Dijkstra 单源最短路算法，可以用堆实现优先队列，将单次节点检索的开销从 $O(n)$ 优化至 $O(logn)$
2. 📈海量数据 $TopK$ 问题：例如从 1 万亿个数据中找到最小的 $100$ 个数，仅需要建立容量为 $100$ 的大顶堆：遍历数据时堆未满直接插入；堆满后若新元素小于堆顶，就替换堆顶并调整堆，最终堆内留存的就是全局最小的 $100$ 个数，极大降低内存占用
3. ⏱️优先队列底层实现：操作系统任务调度、消息队列优先级调度、定时器管理等场景，底层普遍采用堆结构实现

### （六）重点答疑：为什么哈夫曼树不能用堆排序优化建树❓

很多人会混淆堆结构和堆排序的使用边界，这里明确解释：

1. 哈夫曼树的建树规则：**每一轮选出当前权值最小的 $2$ 个节点合并生成新父节点，新生成的节点需要重新放回候选节点池**，候选集合是动态增删的；
2. 堆排序的固定流程：仅能对初始固定数组完成一次性建堆，后续只能把最值移动到数组末尾，候选集合只能持续缩小，不支持动态插入新生成的中间节点；
3. ✅正确用法：哈夫曼建树可以用**堆结构实现的优先队列**完成每次取双最小值的操作，但不能直接用堆排序算法优化建树全过程，二者的执行逻辑、使用场景存在本质区别。
