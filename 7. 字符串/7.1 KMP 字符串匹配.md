> [!note] 写在最前面 KMP 解决的是**字符串匹配问题**：给定主串 p 和模式串 s，判断 s 是不是 p 的一个子串，如果是，找出所有出现位置。暴力做法很直观但最坏 $O(n·m)$；KMP 的全部精妙之处，就在于发现"失配之后，主串指针根本不需要回退"，而模式串指针该回退到哪，最终会被证明**等价于求模式串自身的最长相同前后缀**。这篇笔记把"为什么"这条推导链条完整走一遍，再落到代码。🎯

## 🧱 一、基础概念

### 🔤 1.1 字符串 / 子串 / 前缀子串 / 后缀子串

- **字符串**：由 0 个或多个字符组成的连续序列，字符个数称为串的**长度**，通常用数组保存。
    - `char s[] = "abcd";` → 字符串，末尾隐含一个 `'\0'`；
    - `char a[] = {'a','b','c','d'};` → 单纯的字符数组，没有隐含终止符。
- **子串**：字符串中拿出**连续的一段**。长度为 n 的字符串，子串个数为 `1+2+3+...+n`。 例如 `"abcd"` 的子串：`"a" "b" "c" "d"` / `"ab" "bc" "cd"` / `"abc" "bcd"` / `"abcd"`。
- **前缀子串**：从第一个字符开始、到后面任意一个字符结束（**结束位置不能是最后一个位置**）——`"abcd"` 的前缀子串是 `"a" "ab" "abc"`。
- **后缀子串**：除第一个位置以外，从任意一个位置开始、到最后一个位置结束——`"abcd"` 的后缀子串是 `"bcd" "cd" "d"`。

> [!tip] 为什么前缀不能取全串、后缀不能从头开始 这两个限制是为了保证前缀和后缀都是"真"的（proper），不能是字符串自己本身——不然"最长相同前后缀"永远都是整个串自己，讨论就没有意义了。

### 🪞 1.2 相同前后缀 & 最长相同前后缀

以 `"abababa"` 为例：

```
前缀子串: a  ab  aba  abab  ababa  abababa 的真前缀们
后缀子串: a  ba  aba  baba  ababa  ...     的真后缀们
```

把**长度一样**的一对前缀子串和后缀子串，称为一对**相同前后缀**；其中长度最长的那一对，称为**最长相同前后缀**（这就是后面 `next` 数组的核心含义）。

> [!important] 一条关键性质：短的相同前后缀，一定是长的相同前后缀的相同前后缀 如果一个字符串 s 有多个相同前后缀，其中子串 x 比子串 y 长，那么 **y 一定也是 x 的相同前后缀**。
> 
> 直觉解释：x 本身作为一个字符串，它的前缀和后缀是从 s 的前缀和后缀里"截出来的一段"，s 的相同前后缀关系会原样保留在这个截出来的子串上。这条性质是 KMP 能够"逐级回退、不遗漏任何候选"的理论基础——后面会反复用到它。

> [!note]- 🧩 小例题（巩固上面这条性质） 假设字符串 s 有 6 个相同前后缀，分别是子串 a、b、c、d、e、f，长度依次是 3、5、9、12、15、17。
> 
> **问**：字符串 d（长度 12）自己作为一个字符串，它有几个相同前后缀？最长的是多少？
> 
> **答**：根据上面的性质，s 里所有比 d 短的相同前后缀（也就是 a=3、b=5、c=9）都必然同时也是 d 的相同前后缀——所以 **d 有 3 个相同前后缀，最长的是 c，长度 9**。这也预示着：只要顺着"次长、次次长……"一路退下去，所有候选都不会漏掉，而且这条退的路径是唯一确定的。

### 🔍 1.3 字符串匹配问题的定义

给出两个字符串 p 和 s，把 **p 称为主串，s 称为模式串**。问：主串 p 中是否存在一段连续的序列和 s 匹配上？——换句话说，**s 是不是 p 的一个子串？**

## 🧗 二、从暴力匹配到 KMP：完整推导链条

### 🐢 2.1 暴力匹配：本质是什么

最直观的想法：尝试从 p 的每一个位置开始，和 s 逐字符匹配比较。设从主串第 k 个位置开始匹配：

```c
i = k,  j = 0
while (i 从 k 走到 k+l-1，  j 从 0 走到 l-1)   // 假设前面 l 个字符都匹配上了
p[k+l] != s[l]   // 在 i=k+l, j=l 时失配
```

按照暴力匹配的思路，失配后应该让 **i 回到开始匹配的下一个位置 k+1，j 清零重新匹配**。这样做没有错，但代价很大：每换一个起点都要把已经比对过的信息全部扔掉，从头再来。

### 💡 2.2 大胆的优化猜想：i 真的需要回退吗？

优化的方向是：**失配时，i 不再回到 k+1，让 i 保持在 k+l 不动，只需要让 j 回到前面某个合适的位置即可。** 这是一个相当反直觉的猜想——凭什么可以跳过"从 k+1 重新扫描"这一大段过程？下面证明这件事是站得住脚的。

> [!note]- 🔬 证明：为什么 i 可以不回退（穷举所有情况） 假设按照暴力匹配的思路，让 i 回到 k+1、j 回到 0 继续重新匹配。关键论断是：**在后面的某次匹配过程中，i 迟早会再次走到 k+l 这个位置**（也就是刚刚失配的那个位置）——不管中途经历了什么。
> 
> 当 `i = k+l, j = l` 失配时：
> 
> - **(一) 让 i = k+1, j = 0 继续匹配**：
>     - **情况一**：k+l 之前又刚好一路匹配上了，即 `p[k+1]==s[0], p[k+2]==s[1], ..., p[k+l-1]==s[l-2]`，走到 `i=k+l` 时再比较 `p[k+l]` 和 `s[l-1]`；
>     - **情况二**：k+l 之前没有匹配上，提前再次失配（比如在 i=k+1 就失配了）。此时 i=k+2，j=0，继续匹配——同样又会分出"情况一/情况二"，如果又失配，i 变成 k+3，j=0，继续……
> 
> 不管这个"情况一/情况二"的分支具体走了多少轮，**只要沿着这条路径最终能匹配到 i=k+l 这个位置，它就一定会被走到**（因为每一轮失配都只是让起点往右挪一格，重新尝试，起点最终必然会扫过 k+1、k+2、……、直到某个起点能把 i 带到 k+l）。
> 
> 既然这个"重新扫描、最终走到 i=k+l"的过程结果是确定的、迟早会发生的，那我们完全可以**把这整个重复扫描的过程省略掉**：直接让 i 停在 k+l 不动，转而去推理"如果真的走了这个过程，j 现在应该等于几"。

### ❓ 2.3 新问题：j 应该退到哪？

> [!note]- 🧭 由于没有真的执行"重新匹配"，怎么知道 j 该是多少？ 由于我们并没有真的执行那个重新扫描的过程，所以没法直接观察到"i 再次走到 k+l 位置时，j 走到了几"——必须靠推理，而不是模拟。
> 
> **核心推理**：如果 i 能够走到 k+l，说明从某个新的起点到 k+l-1 这一段，必须重新和 `s[0..j-1]` 匹配上（j 就是我们要求的答案）。但这一段内容我们其实是**已知的**——因为它是原来已经匹配成功的那一段 `p[k..k+l-1]`（也就是 `s[0..l-1]`）的一部分。换句话说：
> 
> **这一段"新对齐、又重新匹配上的前缀"，同时也是"原来已匹配串 s[0..l-1] 的一个后缀"。**
> 
> 而它又必须是 s 自己的一个前缀（因为匹配就是拿 s 从头开始比对）。**同一段内容，既是 s[0..l-1] 的后缀，又是 s 的前缀——这正是"相同前后缀"的定义！** 于是问题被彻底转化了：
> 
> **j 的值，就等于 `s[0..l-1]` 这一段的最长相同前后缀的长度。**

> 
> - 第一层含义：**最长** —— 优先尝试信息利用率最高的候选（保留的已匹配信息最多，之后不匹配的话回退次数也最少）；
> - 第二层含义：**如果最长的候选后续验证失败，要能退到次长的、次次长的……一路退下去，不能漏掉任何一个可能更早出现的合法匹配位置**。
> 
> 这正是「一、1.2」那条"短的相同前后缀一定是长的相同前后缀的相同前后缀"的性质派上用场的地方：它保证了"取最长 → 失败后退到次长"这条路径**能覆盖所有候选、不会跳过任何一个中间可能成立的选项**。next 数组的构造和查找阶段的回退，用的是同一条性质、同一套逻辑。

## 🔢 三、next 数组：定义、两种写法与递推构造

### 📖 3.1 next 数组的经典定义

`next[j]`：当在模式串下标 j 处失配时，下一次应该让 `j = next[j]` 继续比较。如果字符串从下标 0 开始存，`next[j]` 恰好就是 `s[0..j-1]` 这一段的最长相同前后缀的长度。

以模式串 `"abababa"` 为例，假设匹配到 `j=6` 失配了，推理可得下次应该 `j=4` 重新匹配：

```cpp
下标: 0 1 2 3 4 5 6
模式: a b a b a b a

next[0] = -1   （哨兵：已经退无可退，只能让主串指针前进）
next[1] = 0
next[2] = 0
next[3] = 1
next[4] = 2
next[5] = 3
next[6] = 4
```

> [!note]- 🔀 这套"-1 哨兵"写法和最终代码里的写法，是同一个东西吗？ 是的，只是**下标的参照物差了一格**，本质完全等价：
> 
> - **推导用的经典写法**（`next[0]=-1`）：`next[j]` 描述的是"**失配在 j 处时，j 该退到哪**"，需要一个 `-1` 当哨兵，表示"已经退到最左边，没法再退，只能挪动主串指针"。
> - **本笔记最终代码采用的写法**（对应实现里的 `next[i]`）：`next[i]` 描述的是"**`pat[0..i]` 这一段本身的最长相同前后缀长度**"，`next[0]=0` 就够用，不需要 `-1` 哨兵，失配时改用 `if (j != 0)` 显式分支处理"已经退无可退"的情况。
> 
> 换算关系：`经典写法的 next[j] = 代码写法的 next[j-1]`（j ≥ 1）。两者是完全相同的算法，只是一个把"哨兵"编码进数组本身（-1），一个把它拆成一个显式的 if 分支——代码实现选择了后者，避免了 `-1` 这种"魔法下标"带来的理解成本。

### 🧮 3.2 next 数组怎么递推构造（DP 的思路）

next 数组不能暴力地对每个 j 都重新扫一遍字符串去求最长相同前后缀（那样构造本身就退化成 O(m²) 了），而是可以用 **next[j-1] 递推出 next[j]**——这本身也是一次"动态规划"：

> [!note]- 🧩 递推关系怎么来的 把 `next[j]` 看成一个状态数组：**`next[j]` = `s[0..j-1]` 的最长相同前后缀的长度**。
> 
> 已知 `next[j-1]` = `s[0..j-2]` 的最长相同前后缀的长度，设这个长度为 x。观察 `[0, j-1]` 这一段和 `[0, j-2]` 这一段的关系：`[0,j-1]` 的后缀，比 `[0,j-2]` 的后缀**多了一个字符 `s[j-1]`**；对应地，前缀那边也该补一个字符 `s[x]` 才能保持长度相等一起比较。于是：
> 
> - **如果 `s[x] == s[j-1]`**：新补的这一位也对上了，`[0,j-1]` 的最长相同前后缀长度就是 `x + 1`；
> - **如果 `s[x] != s[j-1]`**：长度为 `x+1` 的候选不成立，只能退而求其次，在**更短的**、`[0, x]` 这一段本来就已经算好的相同前后缀基础上继续尝试——也就是 `x = next[x]`，重复上面的判断，直到 x 退到 0（或找到能接上的位置）为止。
> 
> 这正是「二、2.4」里"取最长、失败退到次长"那条思路在**构造阶段的自我复用**：构造 next 数组时，本质是在用模式串**匹配它自己**，遇到"失配"就用已经算好的、更短的 next 值来回退——查找阶段和构造阶段，用的是完全相同的一套回退逻辑。

## 🧱 四、总体框架 & 头文件全貌（代码块 1️⃣）

### 📐 整体架构

依然是命名空间 + 类。这次的类只有一个核心职责：绑定一个模式串，预处理出它的 next 数组，之后可以反复用它去匹配不同的文本——这也是为什么用类而不是写成一个孤立函数：**预处理（O(m)）只做一次，之后每次查找都是 O(n)**，不用重复计算 next 数组。

## ⚙️ 五、核心实现：构造 next 数组 + 查找（代码块 2️⃣）

### 💭 buildNext 的思路

对照「三、3.2」的递推关系："`len` 表示当前已确认的最长相同前后缀长度，能接上就扩展，接不上就退到 `next[len-1]` 再试一次"——代码里的 `len` 就是推导里的 `x`，`pat[i] == pat[len]` 对应"新补的一位是否接得上"，`len = next[len-1]` 对应"退到更短的候选继续尝试"。

### 💭 findAll 的思路

对照「二」整节的推理结论："失配时 text 指针 i 不回退，pattern 指针 j 回退到 `s[0..j-1]` 的最长相同前后缀长度"——代码里就是 `j = next[j-1]`。多了一步是**允许重叠匹配**：完整匹配一次之后（`j == m`），同样用 `j = next[j-1]` 而不是把 `j` 清零，这样在类似 `"aaaa"` 里找 `"aa"` 这种模式串自我重叠的场景下，不会漏掉重叠的匹配。

```cpp
KMPMatcher::KMPMatcher(const std::string& pattern) : pat(pattern) {
    buildNext();
}

void KMPMatcher::buildNext() {
    int m = static_cast<int>(pat.size());
    next.assign(m, 0);
    if (m == 0) return;

    next[0] = 0; // 单个字符自身没有"真前缀"，规定为 0（边界情况）

    int len = 0; // len：当前已经确认的、pat[0..i] 的最长相等真前缀真后缀的长度
    int i = 1;
    while (i < m) {
        if (pat[i] == pat[len]) {
            ++len;
            next[i] = len;
            ++i;
        } else if (len != 0) {
            // 接不上，但 len 不是 0：退而求其次，看更短一档的候选（next[len-1]）行不行，
            // 注意这里没有移动 i，只是候选长度变短了，要用新的 len 再试一次。
            len = next[len - 1];
        } else {
            // len 已经是 0，没有更短的候选可以退了。
            next[i] = 0;
            ++i;
        }
    }
}

std::vector<int> KMPMatcher::findAll(const std::string& text) const {
    std::vector<int> occurrences;
    int m = static_cast<int>(pat.size());
    if (m == 0) return occurrences; // 约定空模式串不匹配任何位置

    int n = static_cast<int>(text.size());
    int i = 0; // text 指针：只前进，不回退
    int j = 0; // pattern 指针：失配时靠 next 数组回退

    while (i < n) {
        if (text[i] == pat[j]) {
            ++i;
            ++j;
            if (j == m) {
                occurrences.push_back(i - j); // 起始位置是 i - j
                j = next[j - 1]; // 继续找下一个匹配（允许重叠），不清零
            }
        } else if (j != 0) {
            j = next[j - 1]; // text 指针 i 完全不动，这正是 O(n) 的关键
        } else {
            ++i; // j 已经是 0，没法再退，只能把 text 指针往后挪一位
        }
    }
    return occurrences;
}

int KMPMatcher::findFirst(const std::string& text) const {
    int m = static_cast<int>(pat.size());
    if (m == 0) return -1;

    int n = static_cast<int>(text.size());
    int i = 0, j = 0;
    while (i < n) {
        if (text[i] == pat[j]) {
            ++i; ++j;
            if (j == m) return i - j; // 找到第一个就直接返回
        } else if (j != 0) {
            j = next[j - 1];
        } else {
            ++i;
        }
    }
    return -1;
}

void KMPMatcher::printFailureTable() const {
    std::cout << "模式串: ";
    for (char c : pat) std::cout << std::setw(3) << c;
    std::cout << "\n下标  : ";
    for (size_t k = 0; k < pat.size(); ++k) std::cout << std::setw(3) << k;
    std::cout << "\nnext[]: ";
    for (int v : next) std::cout << std::setw(3) << v;
    std::cout << "\n";
}
```

## 🎓 七、总结

### ✅ 推导链条回顾（这是这篇笔记最核心的部分）

1. 🐢 **暴力匹配**：每个起点重新扫一遍，失配就让 i 回到 k+1、j 清零——最坏 O(n·m)。
2. 💡 **大胆猜想**：失配后 i 能不能不回退？
3. 🔬 **证明猜想成立**：穷举"i=k+1 重新匹配"的所有分支，发现不管怎么走，i 迟早会走回 k+l 这个位置——既然结果确定，干脆省略这个重复扫描的过程。
4. ❓ **新问题**：i 不动了，那 j 该退到几？由于没有真的执行重新匹配，只能靠推理：能让 i 走到 k+l 的那一段，必然同时是 `s[0..l-1]` 的后缀，也是 s 自己的前缀。
5. 🎨 **图示转化**：四块蓝色区域直观展示"新对齐的前缀"和"已匹配串的后缀"是同一段内容——**j 回退问题，等价于求最长相同前后缀问题**。
6. 🎯 **next 的两层含义**：取"最长"保证信息利用率最高；能"逐级退到次长"保证不遗漏任何候选，后者依赖「一、1.2」那条"短的是长的的相同前后缀"的性质。
7. 🧮 **构造 next 数组**：用模式串匹配自己，递推关系和查找阶段的回退逻辑完全同源。

### 📌 这次的方法论

KMP 最值得记住的不是最终的双指针代码，而是**这条从"暴力"到"最优"的推理路径本身**：先大胆猜想"能不能省掉一步"，再老老实实穷举证明这个猜想为什么成立，最后把"证明过程里那个没有被执行的推理"转化成一个可以直接计算的子问题（最长相同前后缀）。这套"猜想 → 证明 → 转化为可计算子问题"的思路，在很多算法优化里都会反复出现。
