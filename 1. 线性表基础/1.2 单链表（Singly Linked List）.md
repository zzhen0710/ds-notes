### 📌 核心逻辑：从顺序表到链表的存储延伸

顺序表依赖**连续内存**实现线性表逻辑，而链表则打破了 “连续存储” 的限制 —— 它通过**指针**将分散在内存中任意位置的结点串联起来，以此实现 “一对一” 的线性关系，是线性表的另一种核心实现形态。

### **Q🔸：链表的本质是什么？**

A✅️：链表是**以离散结点为存储单元**，通过指针域将数据元素按逻辑顺序串联的线性表。每个结点包含「数据域（存数据）+ 指针域（指向下一结点）」，无需连续内存空间。

### 🔑 核心概念梳理 📝

#### 1. 链表核心指针 / 结点定义

- **头指针**：指向链表第一个结点的指针（带头结点则指向头结点，不带头则指向首元结点），是链表的**唯一入口**（必需项）；
- **头结点**：链表首个结点，数据域无意义，指针域指向首元结点（仅简化操作，可选项）；
- **首元结点**：存储第一个有效数据的结点（带头结点时是第二个结点，不带头时是第一个结点）；
- **结点本质**：`malloc` 申请的内存空间本身无名字，指针是操作结点 / 链表的 “语法替身”，通过指针才能访问结点。
    
    - 补充理解：
        
        1. 核心逻辑：`struct Node *L = (struct Node*)malloc(sizeof(struct Node));` 本质是「申请结点空间 + 让指针 L 指向该空间」；
        2. 指针名 “L” 的双重含义：既代表头指针的名字（指向链表第一个结点的指针），也代表整个链表的名字（因为通过 L 能访问整个链表，就用 L 代指链表）；
        3. 普通结点的 “名字” 规则：只有第一个结点（头结点 / 首元结点）能通过头指针 “L” 间接被指代；链表中其他普通结点，仅能通过指针遍历访问，本身没有专属名字。
        
    

#### 2. 关键结论

- 头指针≠指向头结点的指针（不带头结点时，头指针直接指向首元结点）；
- 链表的 “名字” 本质是头指针（如 `L`），通过头指针可遍历整个链表。

#### 3. 链表遍历 / 操作的核心注意点 ⚠️

##### （1）为什么不用 `Node p = &L` 局部变量遍历，必须用指针遍历？

- 链表的结点存储在**堆内存**（`malloc` 申请），而非栈内存；局部变量 `Node p` 是栈上的拷贝，无法关联到堆内存中的结点；
- 指针遍历的本质：通过指针变量存储堆结点的地址，以此 “指向” 并操作堆中的真实结点；若用局部变量，修改的只是栈上的拷贝，无法改变链表本身的结构 / 数据。

##### （2）尾插法中 `p=L` 从头结点开始遍历的必要性

- 尾插法的核心是找到**尾结点**（指针域为 NULL 的结点）；
- 若链表为空（仅头结点），`p=L->next` 会直接指向 NULL，无法执行后续遍历逻辑；
- 从头结点 `p=L` 开始遍历，可兼容 “空链表” 和 “非空链表” 两种场景：空链表时直接在头结点后插入，非空链表时遍历到尾结点再插入。

### 💻 单链表核心操作代码实现（C 语言）

```c
#include<stdio.h>
#include<stdlib.h>

namespace Linked_List {
	typedef struct Node {
		int data;
		struct Node* next;	// 用来储存每个结点的指针域
	}Node, * LinkList;

	// 初始化一个带头结点的空链表
	Node* InitLink(void)
	{
		// 正确写法：在堆上申请空间并返回
		Node* head = (Node*)malloc(sizeof(Node));
		head->next = NULL;
		return head;
	}

	// 头插法：在头结点之后添加数据x
	// 逻辑步骤：
	// （1）创建结点s，把数据x放到结点s的数据域中
	// （2）结点s的指针域指向原来的首元结点
	// （3）头结点的指针区域指向新结点s
	LinkList headInsert(LinkList L, int x)
	{
		// 创建结点s.  实际上是指针s指向了该结点 后续对结点s的操作 本质上是通过指针s操作结点中的成员变量
		Node* s = (Node*)malloc(sizeof(Node));
		// 结点s的指针域指向原来的首元结点 头结点L的指针域中保存了原首元结点的地址
		s->next = L->next;
		// 把数据x放到结点s的数据域中
		s->data = x;
		// 头结点的指针区域指向新结点s
		L->next = s;

		return L;
	}

	// 尾插法：在尾结点之后添加数据x
	// 注意考虑空表，是从头结点开始找，这与考虑脏数据，从首元结点开始找的Find不同
	// 逻辑步骤：
	// （1）创建结点s，把数据x放到结点s的数据域中，s的指针域为NULL
	// （2）从头结点开始遍历循环找尾结点 p
	// （3）尾结点p之后插入结点s
	LinkList rearInsert(LinkList L, int x)
	{
		// 创建结点s.
		Node* s = (Node*)malloc(sizeof(Node));
		// 从头结点开始遍历（兼容空链表场景）
		Node* p = L;
		// 结点p的指针域不为NULL 说明后面还有结点，继续往后找
		while (p->next != NULL)
		{
			p = p->next; // 继续走到下一个结点
		}
		s->next = NULL;
		s->data = x;
		p->next = s;

		return L;
	}

	// 查找 数据x所在的结点
	// 注意考虑脏数据，是从首元结点开始找，这与考虑空表，从头结点开始找的Find不同
	// 返回值：找到则返回对应结点指针，未找到则返回NULL
	Node* Find(LinkList L, int x)
	{
		// 从首元结点开始找
		Node* p = L->next;
		// 结点p的数据域不为x 说明p不是我们要的结点 继续往后走
		while (p != NULL && p->data != x)
		{
			p = p->next;
		}
		// while循环停止的情况：
		// 1. p为NULL → x不存在
		// 2. p不为NULL并且数据域是x → p是要找的结点
		return p;
	}

	// 指定位置插入数据：在数据k之后插入数据x
	//（注意这里与顺序表不同，顺序表不用Find，因为顺序表知道表长所以关注的是位置k，在位置k上插入）
	// 逻辑步骤：
	// （1）创建结点s，把数据x放到结点s的数据域中
	// （2）从首元结点开始找k所在的结点p
	// （3）结点p之后插入结点s
	LinkList Insert(LinkList L, int k, int x)
	{
		// 先找到数据k所在的结点s
		Node* s = Find(L, k);
		if (s == NULL)
		{
			printf("The insertion failed : The data %d dose not exist.\n", k);
			return L;
		}
		// 创建新结点p用于存储插入的x
		Node* p = (Node*)malloc(sizeof(Node));
		p->next = s->next;
		p->data = x;
		s->next = p;

		return L;
	}

	// 修改操作：将链表中数据k修改为x
	LinkList Change(LinkList L, int k, int x)
	{
		// 找到数据k所在的结点
		Node* s = Find(L, k);
		if (s == NULL)
		{
			printf("The change failed : The data %d dose not exist.\n", k);
			return L;
		}
		// 修改结点的数据域为x
		s->data = x;

		return L;
	}

	// 删除操作：在链表L中删除数据k
	// 逻辑步骤：
	// （1）找到k所在的结点p及其前一个结点pre
	// （2）pre指向p的后一个结点
	// （3）释放p结点的内存
	LinkList Delete(LinkList L, int k)
	{
		// p从首元结点开始 pre从头结点开始 一起往后走
		Node* pre = L, * p = L->next;
		// 遍历找数据k所在的结点p，同时记录前驱结点pre
		while (p != NULL && p->data != k)
		{
			pre = pre->next;
			p = p->next;
		}
		// while循环停止的情况：
		// 1. p为NULL → k不存在
		// 2. p不为NULL并且数据域是k → p是要删除的结点
		if (p == NULL)
		{
			printf("The deletion failed : The data %d dose not exist.\n", k);
		}
		else
		{
			// pre指向p的后一个结点，断开p的链接
			pre->next = p->next;
			// 释放p结点的内存，避免内存泄漏
			free(p);
			// 将p置为NULL，避免野指针
			p = NULL;
		}
		return L;
	}

	// 删除整表，头删法
	// 逻辑：逐个删除首元结点，直到链表为空（仅保留头结点）
	LinkList deleteLink(LinkList L)
	{
		// 只要首元结点存在，就继续删除
		while (L->next != NULL)
		{
			// 指向当前要删除的首元结点
			Node* p = L->next;
			// 头结点指向原首元结点的下一个结点
			L->next = p->next;
			// 释放当前首元结点内存
			free(p);
			// 置空避免野指针
			p = NULL;
		}
		return L;
	}

	// 遍历并打印链表所有数据
	void Show(LinkList L)
	{
		// 从首元结点开始遍历
		Node* p = L->next;
		if (p == NULL)
		{
			printf("The Linked List is empty.");
		}
		else while (p != NULL)
		{
			printf("%d ", p->data);
			p = p->next;
		}
		printf("\n");
	}

	// 测试链表所有操作
	void runTest(void)
	{
		LinkList L = InitLink();
		Show(L);

		L = Insert(L, 100, 1);
		L = Delete(L, 100);
		L = Change(L, 100, 1);
		Show(L);

		//（...内容重复略）
	}
}

void main()
{
	Linked_List::runTest();
}
```

### 📊 链表的优缺点与适用场景

**Q🔸：链表有哪些优缺点？**

A✅️：

#### 1. 优点 ✨

- 无需连续内存空间，**动态扩展 / 收缩**灵活，不会浪费内存；
- 插入 / 删除操作高效（仅需修改指针指向），无需移动大量元素，时间复杂度为 O (1)（找到目标结点后）；
- 头插法 / 尾插法实现简单，适合频繁增删数据的场景。

#### 2. 缺点 ⚠️

- 不支持**随机存取**，访问任意结点需从头指针开始顺序遍历，时间复杂度为 O (n)；
    
    - 补充：顺序表 “随机存取” 的优点在实际开发中**并不常用**（知道位置就无需查找），而链表 “无法随机存取” 的缺点却会显著影响查询效率；
    
- 每个结点额外存储指针域，**空间开销更大**；
- 需手动管理内存（`malloc`/`free`），易出现内存泄漏、野指针等问题。

#### 3. 适用场景 🎯

适合数据**频繁增删、少量查询**的场景（如消息队列、任务链表）；

不适合需要频繁随机访问数据的场景（如排行榜、索引表）。

#### 🔍 链表操作核心技巧 ✨

**Q🔸：单链表操作最重要的关键点是什么？**

A✅️：

在对单链表进行插入、删除等核心操作时，**重点是关注两个指针域**：

1. **前驱结点 pre 的 next 指针域**
2. **新结点 s / 待操作结点的 next 指针域**

只要**合理、有序地操作这两个指针**，就能正确完成结点的插入、删除、链接，稳稳控制整个链表的结构。

这是链表所有复杂操作的**核心本质**。

### 📝 总结

1. 链表通过**指针串联离散结点**实现线性表逻辑，核心是头指针（必需）+ 结点（数据域 + 指针域）；指针是操作堆内存结点的唯一 “桥梁”，局部变量无法替代；
2. 尾插法需从头结点开始遍历，才能兼容空链表场景，避免遍历逻辑异常；
3. 代码实现的核心是「指针操作」（插入 / 删除改指针、遍历靠指针移动）+「内存管理」（`malloc`申请 /`free`释放）；
4. 链表与顺序表互补：链表增删高效但查询慢，顺序表查询快但增删慢，需根据业务场景选择。
