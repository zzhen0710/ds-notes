## 一、📖 基础核心概念

### 1.1 三类图模型对比

关键路径是拓扑排序的延伸应用，二者对应不同的工程建模方式，核心区别如下：

![关键路径 1.png](<../pict/关键路径 1.png>)

### 1.2 事件与活动的区别

- 📌 **事件（顶点）**：瞬间发生的状态节点，不消耗时间；它的发生标志着**所有前置活动结束、所有后置活动可以开始**。
- 📌 **活动（有向边）**：持续执行的过程，消耗时间；从一个事件出发，指向另一个事件。

> 💡 通俗举例：
> 
> 「拿起笔」是事件（瞬间发生），「写作业」是活动（持续 120 分钟），「放下笔」是事件；事件是活动的起止节点。

### 1.3 源点与汇点

- 🔹 **源点**：AOE 网中入度为 0 的顶点，代表整个工程的开始事件。一个工程通常只有一个开始点。
- 🔹 **汇点**：AOE 网中出度为 0 的顶点，代表整个工程的结束事件。一个工程通常只有一个完成点。

### 1.4 关键路径与关键活动

AOE 网中的活动可以并行执行，因此完成工程的最短时间，由**从源点到汇点的最长路径**决定。

- 🚩 **关键路径**：源点到汇点的所有路径中，路径长度（边权和）最大的路径，决定了整个工程的最短总工期。
- 🚩 **关键活动**：关键路径上的活动，核心特征是**没有时间余量**—— 最早开始时间 = 最晚开始时间。
- 🚩 **非关键活动**：不在关键路径上的活动，存在可拖延的时间余量；只要延期不超过余量，就不会影响总工期。

### 1.5 核心性质

1. ✅ 关键路径**不一定唯一**：一个 AOE 网可能有多条长度相同的最长路径，均为合法关键路径。
2. ✅ 关键活动延期 → 整个工程一定延期。
3. ✅ 非关键活动延期 → 工程不一定延期，不超过时间余量则无影响。
4. ✅ 工程总工期 = 关键路径的长度 = 汇点的最早发生时间。

## 二、🧮 四大核心时间量

关键路径的求解本质是计算两组共四个时间量，先算事件维度，再推导活动维度。

### 2.1 事件维度（顶点）

#### （1）事件最早发生时间 ETV /ve (Earliest Time of Vertex)

- 定义：从源点到该顶点的最长路径长度，即该事件**最早可以发生的时间**。
- 计算方向：**正向推导**，按拓扑排序顺序从源点向汇点计算。
- 递推公式：`ve[i] = max{ ve[j] + weight<j,i> }`，对所有指向 i 的入边取最大值。
- 原理：事件必须等所有前置活动都完成才能发生，因此取所有前驱路径的最大值。
- 初始值：源点的最早发生时间 `ve[源点] = 0`。

#### （2）事件最晚发生时间 LTV /vl (Latest Time of Vertex)

- 定义：不推迟整个工程总工期的前提下，该事件**最晚可以发生的时间**。
- 计算方向：**逆向推导**，按逆拓扑排序顺序从汇点向源点计算。
- 递推公式：`vl[i] = min{ vl[j] - weight<i,j> }`，对所有 i 出发的出边取最小值。
- 原理：事件不能耽误任何一个后继活动的最晚开始，因此取所有后继要求的最小值。
- 初始值：汇点的最晚发生时间 = 汇点的最早发生时间，即 `vl[汇点] = ve[汇点] = 总工期`。

### 2.2 活动维度（边）

#### （1）活动最早开始时间 ETE /e (Earliest Time of Edge)

- 定义：该活动最早可以开始执行的时间。
- 计算方式：活动起点事件的最早发生时间 → `e = ve[起点]`。
- 原理：起点事件发生了，活动才能启动。

#### （2）活动最晚开始时间 LTE /l (Latest Time of Edge)

- 定义：不推迟总工期的前提下，该活动最晚可以开始执行的时间。
- 计算方式：活动终点事件的最晚发生时间 - 活动持续时间 → `l = vl[终点] - 活动权值`。
- 原理：活动必须在终点事件最晚发生前完成。

### 2.3 关键活动判定

✅ 当且仅当 `e == l` 时，该活动为关键活动

→ 活动没有任何时间余量，一旦延期就会直接影响总工期。

### 📍补充小节：最长路径与关键路径的关联

#### 1、核心对应关系

AOE 网的**关键路径**本质就是源点到汇点的**最长路径**，二者完全等价，下面分两种场景说明求解思路：

1. **DAG 有向无环图场景（AOE 网标准场景）**
    
    若两个顶点恰好是工程的起点（源点）和终点（汇点），二者之间的最长路径就是该 AOE 网的**关键路径**，直接使用本章 Kahn 拓扑递推法求解，无需转换图。
2. **通用带权图（允许有环）**
    
    无法直接求最长路径，可做等价转换：
    
    将原图所有边的权值全部取相反数，构建负权图；在负权图中求解两点间最短路径，最终最短路径的总权值取相反数，即为原图两点间的最长路径。

#### 2、补充注意点

1. 带环图无法直接用拓扑排序求最长路径，环内可无限循环累加权值，不存在有限最长路径；
2. DAG 图优先使用拓扑序递推最长路径（时间复杂度$O(n+e)$），效率远高于负权转换 + 最短路算法；
3. 只有单源单汇的 AOE 网，源到汇的最长路径才唯一对应工程总工期（关键路径）。

## 三、📝 关键路径算法完整执行步骤

关键路径算法核心是「拓扑序正向递推最早时间、逆拓扑序逆向递推最晚时间、遍历边筛选关键活动」三步核心逻辑。工业实现中主要有两种主流写法：**分步解耦版**和**同步高效版**，二者最终结果完全一致，仅执行流程和代码组织方式不同。

---

### 3.1 版本一：分步解耦版（对应 `ComputeHelper`）

核心设计：拓扑排序与时间计算完全分离，先独立求解拓扑序列，再依次计算 ve、vl、关键活动，逻辑分层清晰，拓扑模块可复用。

#### 第一步：独立求解拓扑序列 + 环检测

1. 🏗️ 建图：邻接表存储 AOE 网，统计每个顶点的入度。
2. 🔍 初始化队列：所有初始入度为 0 的源点入队。
3. 🔄 执行 Kahn 拓扑排序：
    
    - 出队顶点 u，加入拓扑结果序列；
    - 遍历 u 的所有出边 `u→v`，将 v 的入度减 1；
    - 若 v 入度减为 0，则 v 入队；
    - 循环直到队列为空。
    
4. ✅ 合法性校验：若拓扑序列长度≠顶点总数，说明图存在环，无法求解关键路径，抛出异常。

#### 第二步：正向拓扑序 → 递推事件最早发生时间 ve

1. 📏 初始化：所有事件的 ve 数组初始化为 0，源点天然满足 `ve[源点] = 0`。
2. 🔄 按拓扑序列正序遍历每个顶点 u：
    
    - 遍历 u 的所有出边 `u→v`；
    - 用 `ve[u] + 边权` 尝试更新 `ve[v]`，取最大值；
    - 原理：事件必须等所有前置活动都完成才能发生，因此取所有前驱路径的最大值。
    
3. ⏱️ 确定总工期：总工期 = 汇点的最早发生时间 `ve[汇点]`。

#### 第三步：逆向逆拓扑序 → 递推事件最晚发生时间 vl

1. 📏 初始化：所有事件的 vl 数组初始化为总工期，汇点天然满足 `vl[汇点] = ve[汇点]`。
2. 🔄 按拓扑序列逆序遍历每个顶点 u（从汇点倒推回源点）：
    
    - 遍历 u 的所有出边 `u→v`；
    - 用 `vl[v] - 边权` 尝试更新 `vl[u]`，取最小值；
    - 原理：事件不能耽误任何后继活动的最晚开始，因此取所有后继要求的最小值。
    

> 💡 巧妙设计：无需额外构建逆邻接表，正向遍历出边即可更新前驱的 vl，空间更优。

#### 第四步：遍历全边 → 筛选关键活动

1. 🔍 遍历图中所有有向边，对每条边代表的活动分别计算：
    
    - 活动最早开始时间 `e = ve[起点事件]`
    - 活动最晚开始时间 `l = vl[终点事件] - 活动持续时间`
    
2. ✅ 关键活动判定：若 `e == l`，说明该活动无任何时间余量，为关键活动，加入结果集。

---

### 3.2 版本二：同步高效版（对应 `ComputeHelperInline`）

核心设计：拓扑排序的过程中同步计算 ve，一趟遍历完成，减少一次全图遍历，性能更优，完全匹配图示 8 步实现思路。

#### 阶段 1：拓扑排序 + 同步计算事件最早发生时间 ve（对应思路 1-4）

1. 🏗️ 建图：邻接表存储 AOE 网，同时统计每个顶点的入度。
2. 🔍 找起点：所有初始入度为 0 的源点入队。
3. 📏 初始化：所有事件的 ve 初始化为 0，源点自然满足 `ve[s] = 0`。
4. 🔄 执行 Kahn 拓扑排序，同步更新 ve：
    
    - 出队顶点 u，加入拓扑序列；
    - 遍历 u 的所有出边 `u→v`，用 `ve[u] + 边权` 尝试更新 `ve[v]`，取最大值；
    - v 的入度减 1，若入度为 0 说明所有前驱处理完毕，ve 值已最终确定，v 入队；
    - 循环直到队列为空。
    

#### 阶段 2：逆拓扑序 + 求事件最晚发生时间 vl（对应思路 5-6）

5. 📏 初始化：所有事件的 vl 初始化为总工期（ve [汇点]），汇点值天然正确。
6. 🔄 逆序遍历拓扑序列：
    
    - 取出当前顶点 u，遍历 u 的所有出边 `u→v`；
    - 用 `vl[v] - 边权` 尝试更新 `vl[u]`，取最小值；
    - 循环直到处理完所有顶点。
    

#### 阶段 3：遍历所有边 + 筛选关键活动（对应思路 7-8）

7. 🔍 遍历图中所有边，计算每个活动的最早开始时间 e 和最晚开始时间 l。
8. ✅ 判定：若 `e == l`，则该活动为关键活动，加入结果集。

## 四、⚠️ 逆向递推循环的细节与坑点

针对逆拓扑序遍历的循环边界问题，详细说明如下：

### 4.1 单汇点场景的优化

单源单汇的标准 AOE 网中，拓扑序列的最后一个元素一定是汇点，而汇点出度为 0，没有出边。

如果从`n-1`（最后一个元素）开始遍历，汇点的循环是空循环，无实际操作。

因此单汇点场景可优化为从`n-2`开始遍历，跳过汇点，减少一次空循环。

### 4.2 多汇点场景的坑点

如果 AOE 网存在多个汇点（多个出度为 0 的顶点），**拓扑序列的末尾不一定全是汇点**。

- 原因：拓扑排序只保证前驱一定在后继前面，多个汇点之间没有依赖关系，入队顺序会影响它们在拓扑序列中的位置，汇点可能出现在序列中后段，而非全部集中在末尾。
- 风险：此时直接从`n-2`开始遍历，会漏掉部分非末尾的汇点，导致 vl 计算错误。

### 4.3 通用最优方案

1. ✅ 通用保底：从`n-1`开始全量遍历，适配所有场景（单汇 / 多汇），仅多几次空循环，无逻辑错误。
2. ✅ 优化方案：提前标记所有汇点，遍历过程中遇到汇点直接跳过，既避免空循环，又保证多汇点正确性。

> 📌 代码中默认采用全量遍历保证通用性，同时通过注释标注了优化思路。

### 🧩 模块 4：核心算法 - 分步解耦版（ComputeHelper）

#### ✨ 设计特点对比

- **优势**：拓扑排序逻辑完全复用 TopologicalSort 类，单一职责、代码解耦；环检测由拓扑模块统一处理，无需重复实现；逻辑分层清晰，易于调试维护。
- **劣势**：需要额外存储完整拓扑序列，多一次全图遍历，性能略低于同步版。

```cpp
    // ====================== 核心算法：分步递推版 ======================
    void CriticalPath::ComputeHelper(const AL& graph) {
        int n = graph.GetVertexCount();

        // ==============================================================
        // 算法第1步：复用拓扑排序类获取拓扑序列 + 环检测
        // Kahn 算法统一由 TopologicalSort 维护，此处不再重复实现
        // 若图有环，拓扑排序会自动抛出异常，此处无需重复校验
        // ==============================================================
        topological_sort::TopologicalSort ts;
        ts.Compute(graph);
        std::vector<int> topo_order = ts.GetIndexResult();

        int sink = topo_order.back();  // 工程终点事件（汇点）

        // ==============================================================
        // 算法第2步：正向递推 → 事件最早发生时间 ve (vertex earliest)
        // 公式：ve[j] = max( ve[i] + weight<i,j> )  对所有入边<i,j>取最大值
        // 原理：事件必须等所有前置活动都完成才能发生，因此取最长路径的值
        // 初始化：源点的最早发生时间为0
        // ==============================================================
        ve_.resize(n, 0);
        for (int u : topo_order) {
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;
                // 取所有前驱路径的最大值，更新后继事件的最早发生时间
                ve_[v] = std::max(ve_[v], ve_[u] + w);
            }
        }
        total_duration_ = ve_[sink]; // 总工期 = 汇点的最早发生时间

        // ==============================================================
        // 算法第3步：逆向递推 → 事件最晚发生时间 vl (vertex latest)
        // 公式：vl[i] = min( vl[j] - weight<i,j> )  对所有出边<i,j>取最小值
        // 原理：事件最晚不能耽误所有后继活动的最晚开始时间
        // 初始化：汇点的最晚发生时间 = 最早发生时间（总工期固定）
        // 💡 技巧：无需构建逆邻接表，正向遍历出边即可更新前驱的vl
        // ==============================================================
        vl_.resize(n, total_duration_);
        // 按逆拓扑序遍历（从汇点倒推回源点）
        for (int i = n - 1; i >= 0; --i) {
            int u = topo_order[i];
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;
                // 取所有后继路径的最小值，更新前驱事件的最晚发生时间
                vl_[u] = std::min(vl_[u], vl_[v] - w);
            }
        }

        // ==============================================================
        // 算法第4步：遍历所有边，筛选关键活动
        // 对活动 <i,j>（持续时间w）：
        //   最早开始时间 e = ve[i]
        //   最晚开始时间 l = vl[j] - w
        // 关键活动判定：e == l（活动无时间余量，推迟会影响总工期）
        // ==============================================================
        for (int u = 0; u < n; ++u) {
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;

                int e = ve_[u];          // 活动最早开始 = 起点事件最早发生
                int l = vl_[v] - w;      // 活动最晚开始 = 终点事件最晚发生 - 活动时长

                // 无时间余量 → 关键活动
                if (e == l) {
                    critical_acts_.emplace_back(
                        graph.GetVertex(u),
                        graph.GetVertex(v),
                        w
                    );
                }
            }
        }
    }
```

### ⚡ 模块 5：核心算法 - 同步高效版（ComputeHelperInline）

#### ✨ 设计特点对比

- **优势**：拓扑排序的同时计算 ve，一趟遍历完成，减少一次全图遍历，性能更优；无需依赖外部拓扑类，代码自包含；完全匹配图中的 8 步实现思路。
- **劣势**：拓扑排序和 ve 计算耦合，复用性稍差；代码逻辑相对紧凑，调试难度略高。

```cpp
    // ====================== 核心算法：同步递推版 ======================
    void CriticalPath::ComputeHelperInline(const AL& graph) {
        int n = graph.GetVertexCount();

        // ==============================================================
        // 对应思路1-4：Kahn拓扑排序 + 同步计算事件最早发生时间 ve
        // 核心原理：顶点入度减为0时，所有前驱事件均已处理完毕，ve值最终确定
        // 此时用该顶点更新其所有后继的ve，同时继续推进拓扑排序
        // ==============================================================
        std::vector<int> in_degree(n, 0);   // 各顶点入度
        std::queue<int> q;                  // 零入度顶点辅助队列
        std::vector<int> topo_order;        // 拓扑序列（后续逆序算vl仍需使用）

        // 思路3：所有事件最早发生时间初始化为0，源点自然满足 ve[源点] = 0
        ve_.resize(n, 0);

        // 思路1：统计所有顶点的入度
        for (int u = 0; u < n; ++u) {
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                in_degree[v]++;
            }
        }

        // 思路2：所有初始入度为0的源点入队，其ve值已初始化完成
        for (int i = 0; i < n; ++i) {
            if (in_degree[i] == 0) {
                q.push(i);
            }
        }

        // 思路4：拓扑排序主循环，同步更新后继顶点的ve
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            topo_order.push_back(u); // 记录拓扑序列

            // 用当前已确定ve的顶点u，更新其所有出边邻接点的ve
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;

                // 正向递推：ve[v] 取所有前驱路径的最大值
                ve_[v] = std::max(ve_[v], ve_[u] + w);

                // 入度-1；若减为0说明所有前驱处理完毕，ve已最终确定，入队
                if (--in_degree[v] == 0) {
                    q.push(v);
                }
            }
        }

        // 合法性校验：拓扑序列长度≠顶点数 → 图存在环
        if (topo_order.size() != n) {
            throw std::runtime_error("Compute failed: graph contains cycles, cannot compute critical path.");
        }

        int sink = topo_order.back();   // 工程终点（汇点）
        total_duration_ = ve_[sink];    // 总工期 = 汇点的最早发生时间


        // ==============================================================
        // 对应思路5-6：逆拓扑序递推事件最晚发生时间 vl
        // 思路5：汇点的最晚发生时间 = 最早发生时间（总工期固定）
        // 思路6：逆序遍历拓扑序列，用后继顶点的vl更新当前顶点的vl
        // ==============================================================
        // 思路5：所有点初始化为总工期，汇点的值天然正确
        vl_.resize(n, total_duration_);
        // 逆拓扑序遍历（单汇点可从n-2开始优化，此处全量遍历保证多汇点兼容性）
        for (int i = n - 1; i >= 0; --i) {
            int u = topo_order[i];
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;
                // 逆向递推：vl[u] 取所有后继路径的最小值
                vl_[u] = std::min(vl_[u], vl_[v] - w);
            }
        }


        // ==============================================================
        // 对应思路7-8：遍历所有边，筛选关键活动
        // 思路7：计算每条边（活动）的最早开始时间e、最晚开始时间l
        // 思路8：e == l → 活动无时间余量，即为关键活动
        // ==============================================================
        for (int u = 0; u < n; ++u) {
            auto adj_edges = graph.GetAdjacentEdges(u);
            for (const auto& edge : adj_edges) {
                int v = edge.first;
                int w = edge.second;

                int e = ve_[u];          // 活动最早开始 = 起点事件最早发生时间
                int l = vl_[v] - w;      // 活动最晚开始 = 终点事件最晚发生时间 - 活动时长

                if (e == l) {
                    critical_acts_.emplace_back(
                        graph.GetVertex(u),
                        graph.GetVertex(v),
                        w
                    );
                }
            }
        }
    }
```

## 六、⚡ 时间与空间复杂度分析

### 6.1 时间复杂度

基于邻接表存储的关键路径算法：

- 拓扑排序阶段：遍历所有顶点和边，开销 $O(n+e)$
- 正向递推 ve：遍历所有顶点和边，开销 $O(n+e)$
- 逆向递推 vl：遍历所有顶点和边，开销 $O(n+e)$
- 筛选关键活动：遍历所有边，开销 $O(e)$

**总时间复杂度：$O(n+e)$**，和拓扑排序同阶。

### 6.2 空间复杂度

- 辅助数组：ve、vl、入度数组、拓扑序列、辅助队列，均为 $O(n)$
- 邻接表本身开销 $O(n+e)$
    
    **总空间复杂度：$O(n+e)$**

## 七、💼 实际应用与工程意义

### 7.1 历史背景

关键路径法（CPM）1956 年由美国杜邦公司提出，1957 年首次应用于 1000 万美元的化工厂建设项目，工期比原计划缩短 4 个月；杜邦公司使用该方法的第一年就节省了 100 万美元。

### 7.2 核心管理思想

> 🎯 **向关键路径要时间，向非关键路径要资源**
> 
> - 关键活动：优先分配资源、挖掘潜力、压缩时长，直接缩短总工期
> - 非关键活动：在不影响总工期的前提下，抽调人力物力支援关键路径，实现资源最优配置
> - 风险规避：尽量将不可控的任务安排在非关键路径上，降低延期风险

### 7.3 常见应用场景

- 工程项目进度管理（建筑施工、软件开发、大型活动筹备）
- PMP 项目管理认证核心考点
- 生产流程优化、供应链调度
- 任务依赖系统的工期估算与瓶颈识别

## 八、🎓 408 高频考点与避坑指南

### 8.1 核心考点速记

1. ✅ AOE 网定义：边表示活动，顶点表示事件，带权有向无环图
2. ✅ 关键路径定义：源点到汇点的最长路径，决定工程总工期
3. ✅ 四大时间量：$ve$ 正向取 $max$，$vl$ 逆向取 $min$；$e = ve [起点]$，$l = vl [终点] - 权值$
4. ✅ 关键活动判定：$ve == vl$
5. ✅ 时间复杂度：邻接表实现为 $O(n+e)$
6. ✅ 关键路径不唯一；只有所有关键路径都缩短，总工期才会缩短
7. ✅ 关键活动延期一定影响总工期，非关键活动延期不一定

### 8.2 常见易错点

1. ❌ 搞反计算方向：$ve$ 是拓扑序正向计算，$vl$ 是逆拓扑序反向计算
2. ❌ 搞反 $max/min$：$ve$ 取 $max$（等所有前置完成），$vl$ 取 $min$（不能耽误任何后继）
3. ❌ 认为关键路径唯一：可能有多条长度相同的最长路径
4. ❌ 认为缩短任意关键活动都能缩工期：若活动不在所有关键路径上，仅缩短一条无效
5. ❌ 混淆 AOV 与 AOE：AOV 顶点表示活动（拓扑排序），AOE 边表示活动（关键路径）

### 8.3 手动推导技巧

1. 先画图标清顶点与边权
2. 按拓扑顺序逐个计算 $ve$，每个顶点看所有入边取最大值
3. 按逆拓扑顺序逐个计算 $vl$，每个顶点看所有出边取最小值
4. 对每条边计算 $ve$ 和 $vl$，相等即为关键活动
5. 关键活动首尾相连，即为关键路径
