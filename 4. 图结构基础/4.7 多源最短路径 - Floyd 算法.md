> [!note] Floyd 算法解决的是**多源最短路径问题**：给定一个含 n 个点、m 条边的带权有向图，一次算法跑完就能拿到**任意两点之间**的最短距离。它的本质是一道**动态规划**题——"中转点"就是阶段变量，状态转移方程只有一行，但从三维压缩到二维（降维）这一步藏着不少值得推敲的细节。这篇笔记把推导过程、降维的正确性证明、以及基于邻接矩阵的完整 C++ 实现都放在一起。🎯

## 🌱 一、概念、性质与来龙去脉

### 🛣️ 1.1 起源：单源 → 多源的最短路径谱系

最短路径算法不是只有 Floyd 一种，它们的适用范围逐级放宽，也逐级"更贵"：

![Floyd 1.png](<../pict/Floyd 1.png>)

> [!tip] 单源 vs 多源 **单源最短路径算法**：执行一次，只能求出"某一个点"到其它点的最短路径。 **多源最短路径算法**：执行一次，就能求出**任意两点**之间的最短路径——这正是 Floyd 算法的定位，代价是它默认要对所有点两两求解，时间复杂度天然是 O(V³)。

### 🧠 1.2 为什么这是一道动态规划题

最短路径问题符合动态规划的两个经典特征：

- 🧩 **最优子结构**：如果 i 到 j 的最短路径经过某个中转点 k，那么 i 到 k 的这一段、k 到 j 的这一段，也必然分别是各自的最短路径（否则拼起来就不是最短的）。
- ♻️ **重叠子问题**：不同的 (i, j) 对，在求解过程中会反复用到相同的"i 到 k 的最短距离"这类子问题，值得用数组存下来避免重复计算。

### 🎯 1.3 从暴力思路到状态转移方程：完整推导

> [!note]- 💡 起点：能不能借鉴 Dijkstra 的"中转点"思想？ Dijkstra 更新距离的核心语句是：
> 
> ```
> if (dist[i] > dist[k] + g[k][i]) dist[i] = dist[k] + g[k][i];
> ```
> 
> 也就是"用 k 做中转点，看看能不能让 s 到 i 更短"。这启发了一个问题：**怎么样才能让两点之间的距离变得更短？** 答案是——尝试在两点之间引入中转点，**引入的中转点越多，变短的可能性就越大**。Dijkstra 每次只固定一个当前最近的点 k 来更新，而 Floyd 的思路更彻底：**让所有 n 个点都有机会依次充当中转点**。

> [!note]- 📦 第一步：定义状态数组 把问题重新表述为："这 n 个点都可以做中转点的情况下，图中 i 到 j 之间的最短距离是多少？" 用邻接矩阵 `g[n][n]` 存图（初始时 `g[i][j]` 就是直接边权，`g[i][i] = 0`），定义：
> 
> - `dp[k][i][j]` = **从前 k 个点（1~k 号）中选若干个点做中转点**，i 到 j 之间的最短距离。
> 
> 三种状态：
> 
> - **初始状态**：`dp[0][i][j] = g[i][j]`（没有任何中转点，就是原始边权）；
> - **中间状态**：`dp[k][i][j]`（从前 k 个点里挑若干个做中转点）；
> - **最终状态**：`dp[n][i][j]`（n 个点全部可选做中转点，也就是最终答案）。

> [!note]- 🔀 第二步：推导状态转移方程 已知 `dp[0][i][j] ~ dp[k-1][i][j]`，要求 `dp[k][i][j]`。多出来的这第 k 个点，要么用、要么不用：
> 
> - **不经过 k**：最短距离还是 `dp[k-1][i][j]`；
> - **经过 k 中转**：最短距离是 `dp[k-1][i][k] + dp[k-1][k][j]`（i 先走到 k，再从 k 走到 j，中间都只用前 k-1 个点做中转）。
> 
> 两者取更小的一个：
> 
> ```
> dp[k][i][j] = min( dp[k-1][i][j],  dp[k-1][i][k] + dp[k-1][k][j] )
> ```
> 
> 这就是 Floyd 算法唯一的状态转移方程。

### 🗜️ 1.4 降维优化：从三维压成二维

> [!note]- 📉 朴素实现的问题 按状态转移方程，`dp[k][i][j]` 依赖 `dp[k-1][*][*]`，朴素写法要开一个 `dp[n+1][n][n]` 的三维数组，空间 O(n³)，n 稍大就爆内存。观察发现每一层只用到"上一层"，于是尝试直接压成二维、原地更新：
> 
> ```
> dp[k][i][j] = min( dp[k-1][i][j],  dp[k-1][i][k] + dp[k-1][k][j] )
>        ↓  降维
> dp[i][j]    = min( dp[i][j],       dp[i][k]      + dp[k][j] )
> ```
> 
> 但原地更新意味着算 `dp[i][j]` 的时候，等号右边的 `dp[i][k]`、`dp[k][j]` 有可能已经被**本轮（第 k 轮）更新过**，也可能还没被更新——这样算出来的还是正确答案吗？这一步必须证明，不能想当然。

> [!note]- ✅ 降维正确性证明 假设当前 `dp[i][j]` 对应的是 `dp[k-1][i][j]`，正在进行"自我更新"：已经更新过的部分变成了 `dp[k][i][j]`，还没更新的部分仍然是 `dp[k-1][i][j]`，全部更新完之后就统一都是 `dp[k][i][j]` 了。
> 
> **关键结论：第 k 行和第 k 列，在这一轮更新过程中根本不会发生变化**（也就是 `dp[·][k][k] = 0`，恒定）。具体验算：
> 
> - **第 k 行**（i = k 时）： `dp[k][k][j] = min( dp[k-1][k][j], dp[k-1][k][k] + dp[k-1][k][j] )` 因为 `dp[k-1][k][k] = 0`（一个点到自己的最短距离在没有负环时恒为 0），后半项恒等于 `dp[k-1][k][j]`，跟前半项一样，min 出来还是 `dp[k-1][k][j]`——**这一行的值不会变**。
>     
> - **第 k 列**（j = k 时）： `dp[k][i][k] = min( dp[k-1][i][k], dp[k-1][i][k] + dp[k-1][k][k] )` 同理，`dp[k-1][k][k] = 0`，这一列的值也**不会变**。
>     
> 
> 既然第 k 行、第 k 列全程不变，那么不管 `dp[i][k]`、`dp[k][j]` 读到的是"这一轮还没被碰过的旧值"还是"本轮意外被更新但其实等于旧值的新值"，结果都完全一样。**降维之后，仍然按照 i 从前往后、j 从前往后正常遍历更新即可，不需要任何额外处理。**

## 🧱 二、总体框架 & 头文件全貌（代码块 1️⃣）

### 📐 整体架构

沿用一贯的组织方式：**命名空间 + 类**，public 负责对外契约与边界检查（顶点编号合法性、是否已经跑过算法），private 负责核心算法与内部状态。三文件分工：

- `FloydGraph.h`：声明
- `FloydGraph.cpp`：实现（建图 + 核心算法 + 查询）
- `main.cpp`：自动演示 + 交互菜单
- `Utils.h` / `Utils.cpp`：复用的安全输入函数 `getInt`

> [!tip] 一个贯彻到底的设计巧思 `dist` 这块矩阵**身兼两职**：`floydWarshall()` 之前，它就是普通的邻接矩阵（`addEdge` 直接写在这块矩阵里）；跑完之后，它**原地**变成了全源最短距离矩阵。图的存储和 dp 数组用的是**同一块内存**——这是"降维"这件事被贯彻到底的体现，不只是把三维数组压成二维那么简单，而是干脆连"另开一块 dp 数组"这一步都省掉了。

```cpp
/**
 * @file FloydGraph.h
 * @brief Floyd-Warshall 全源最短路径算法模块文件——只包含类的声明（接口）。
 *
 * 邻接矩阵存图 + 状态转移方程 dp[k][i][j]=min(dp[k-1][i][j], dp[k-1][i][k]+dp[k-1][k][j])
 * 降维成 dp[i][j]=min(dp[i][j], dp[i][k]+dp[k][j])，原地更新。完整推导见笔记「一、4」。
 */

#ifndef FLOYD_GRAPH_H
#define FLOYD_GRAPH_H

#include <vector>
#include <string>
#include <limits>

namespace GraphADT {

    /// 边权类型。用 int 是最常见的教学选择，如果需要浮点权重可以改成 double。
    using Weight = int;

    /// 表示"无穷大/不可达"的哨兵值；除以2是为了给两数相加留安全余量，防止溢出。
    constexpr Weight INF = std::numeric_limits<Weight>::max() / 2;

    /**
     * @class FloydGraph
     * @brief 基于邻接矩阵的有向带权图，支持 Floyd-Warshall 全源最短路径。
     */
    class FloydGraph {
    public:
        /// 构造一个含 vertexCount 个顶点、暂无任何边的图（顶点编号 0 ~ vertexCount-1）。
        explicit FloydGraph(int vertexCount);

        /// 添加/更新一条边 u -> v，权值为 w；bidirectional=true 时同时添加反向边。
        void addEdge(int u, int v, Weight w, bool bidirectional = false);

        /// 运行 Floyd-Warshall 算法（降维后的dp，原地更新同一块矩阵）。
        void floydWarshall();

        /// 查询 u 到 v 的最短距离；若不可达，返回 INF。
        Weight getDistance(int u, int v) const;

        /// 复原 u 到 v 的具体最短路径（结点编号序列）；不可达返回空。
        std::vector<int> getPath(int u, int v) const;

        /// 检测图中是否存在负权环（依据：跑完后某个 dist[i][i] < 0）。
        bool hasNegativeCycle() const;

        /// 打印当前矩阵（跑之前是邻接矩阵，跑完后是最短距离矩阵）。
        void printDistanceMatrix() const;

        /// 打印 u 到 v 的具体路径与总权重。
        void printPath(int u, int v) const;

        int vertexCount() const { return n; }

    private:
        int n; ///< 顶点数量

        /// 降维后的 dp 数组：兼职“邻接矩阵”与“最短距离矩阵”，见上方设计巧思说明。
        std::vector<std::vector<Weight>> dist;

        /// 路径复原用的“下一跳”矩阵：nextHop[i][j] 表示 i 到 j 的最短路径上第一步该走到哪。
        std::vector<std::vector<int>> nextHop;

        /// 边界检查：顶点编号必须落在 [0, n) 内。
        void validateVertex(int v) const;
    };

    void runAutoDemo();
    void runInteractiveMenu();

} // namespace GraphADT

#endif // FLOYD_GRAPH_H
```

## 🏗️ 三、建图：构造与 addEdge（代码块 2️⃣）

### 💭 思路

构造函数对应状态转移方程里的**初始状态** `dp[0][i][j] = g[i][j]`：对角线（自己到自己）设为 0，其余全设为 INF（暂不可达），之后 `addEdge` 每调用一次，就是往这块"初始 dp 矩阵"里填一条真实边权，本质就是在搭建 `g[n][n]` 这个邻接矩阵。

```cpp
FloydGraph::FloydGraph(int vertexCount) : n(vertexCount) {
    if (n <= 0) {
        throw std::invalid_argument("顶点数量必须为正整数");
    }
    // 初始化邻接矩阵：自己到自己距离为 0，其余暂时都是"不可达"(INF)，
    // 等 addEdge 陆续把真实边权写进来。
    dist.assign(n, std::vector<Weight>(n, INF));
    for (int i = 0; i < n; ++i) {
        dist[i][i] = 0;
    }
}

void FloydGraph::validateVertex(int v) const {
    if (v < 0 || v >= n) {
        throw std::out_of_range("顶点编号越界");
    }
}

void FloydGraph::addEdge(int u, int v, Weight w, bool bidirectional) {
    validateVertex(u);
    validateVertex(v);
    dist[u][v] = w; // 直接写在邻接矩阵里；如果重复添加同一条边，后添加的覆盖前面的
    if (bidirectional) {
        dist[v][u] = w;
    }
}
```

## 🧮 四、核心算法：floydWarshall（降维DP的代码落地）（代码块 3️⃣）

### 💭 思路

这个函数就是把「一、1.3」推导出的状态转移方程、「一、1.4」证明过的降维正确性，直接翻译成三重循环：

- **最外层 k**：必须放在最外层，这是降维能成立的前提——它保证进入 i、j 这一层循环时，`dist[i][k]` 和 `dist[k][j]` 已经是"只经过前 k-1 个点中转"之后的最短距离，满足状态转移方程对上一层的依赖；
- **中间层 i、最内层 j**：对每一对 (i, j)，检查"经过 k 中转"是否比当前已知的距离更短，是则更新，同时更新 `nextHop`（用于事后复原路径：i→j 要先经过 k，那 i→j 的下一跳就直接复用 i→k 的下一跳，沿着走迟早会经过 k）。
- **两处 `continue` 剪枝**：如果 i 到 k 都不通，经过 k 中转毫无意义，直接跳过，这是纯粹的效率优化，不影响正确性，顺带也避免了两个 INF 相加。

```cpp
void FloydGraph::floydWarshall() {
    // 初始化"下一跳"矩阵：i 到 j 若有直接边（或 i==j），下一跳就是 j 本身；否则 -1。
    nextHop.assign(n, std::vector<int>(n, -1));
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            if (i == j || dist[i][j] < INF) {
                nextHop[i][j] = j;
            }
        }
    }

    // 三重循环，直接在 dist 矩阵上原地跑 dp（降维正确性证明见笔记「一、1.4」）。
    for (int k = 0; k < n; ++k) {
        for (int i = 0; i < n; ++i) {
            if (dist[i][k] >= INF) continue; // i 到 k 都不通，经过 k 中转毫无意义，剪枝
            for (int j = 0; j < n; ++j) {
                if (dist[k][j] >= INF) continue; // k 到 j 不通，同样剪枝

                Weight viaK = dist[i][k] + dist[k][j]; // 经过 k 中转的候选距离
                if (viaK < dist[i][j]) {
                    dist[i][j] = viaK;
                    // i->j 现在要先经过 k，所以 i->j 的下一跳复用 i->k 的下一跳。
                    nextHop[i][j] = nextHop[i][k];
                }
            }
        }
    }
}
```

> [!warning] 复杂度提醒 三重循环，时间复杂度雷打不动是 **O(V³)**。这也是为什么 Floyd 只适合中小规模的图（顶点数几百到一千出头比较舒服），顶点数上万时通常要退回到"对每个点跑一次 Dijkstra"（O(V·ElogV)）这种多源最短路径的替代方案。

## 🔎 五、查询与路径复原（代码块 4️⃣）

### 💭 思路

跑完 `floydWarshall()` 之后，`dist[u][v]` 就是 O(1) 直接能查的最短距离；但很多时候只知道"多远"不够，还想知道"具体怎么走"——这就是 `nextHop` 矩阵的用途：从 u 出发，不断查表"下一步该去哪"，一路走到 v，走过的每一步都保证仍然在最短路径上。`hasNegativeCycle()` 则是利用了「一、1.4」证明里用到的那条性质的逆命题：**正常情况下 `dist[i][i]` 恒为 0，如果变成负数，说明存在一条从 i 出发绕一圈回到 i、总权重为负的路径**，也就是负环。

```cpp
Weight FloydGraph::getDistance(int u, int v) const {
    validateVertex(u);
    validateVertex(v);
    return dist[u][v];
}

std::vector<int> FloydGraph::getPath(int u, int v) const {
    validateVertex(u);
    validateVertex(v);

    if (nextHop.empty()) {
        return {}; // 还没跑过 floydWarshall，没法复原路径
    }
    if (nextHop[u][v] == -1) {
        return {}; // u 到 v 不可达
    }

    std::vector<int> path;
    path.push_back(u);
    while (u != v) {
        u = nextHop[u][v];
        path.push_back(u);
    }
    return path;
}

bool FloydGraph::hasNegativeCycle() const {
    // 正常情况下任何点到自己的最短距离恒为 0；如果变成负数，
    // 说明存在一条从该点出发、绕一圈回到自身、总权重为负的路径。
    for (int i = 0; i < n; ++i) {
        if (dist[i][i] < 0) {
            return true;
        }
    }
    return false;
}

void FloydGraph::printDistanceMatrix() const {
    std::cout << "     ";
    for (int j = 0; j < n; ++j) std::cout << std::setw(6) << j;
    std::cout << "\n";
    for (int i = 0; i < n; ++i) {
        std::cout << std::setw(3) << i << " |";
        for (int j = 0; j < n; ++j) {
            if (dist[i][j] >= INF) std::cout << std::setw(6) << "INF";
            else std::cout << std::setw(6) << dist[i][j];
        }
        std::cout << "\n";
    }
}

void FloydGraph::printPath(int u, int v) const {
    std::vector<int> path = getPath(u, v);
    if (path.empty()) {
        std::cout << u << " -> " << v << " 不可达\n";
        return;
    }
    std::cout << u << " -> " << v << " 最短路径: ";
    for (size_t i = 0; i < path.size(); ++i) {
        std::cout << path[i];
        if (i + 1 < path.size()) std::cout << " -> ";
    }
    std::cout << "（总权重 = " << dist[u][v] << "）\n";
}
```

## 🎓 六、总结

### ✅ 核心回顾

- Floyd 解决的是**多源最短路径**问题，前提是图中**不含负权回路**；BFS 处理无权图单源、Dijkstra 处理不含负权边的图单源，三者是同一问题在不同约束下的谱系。
- 最短路径问题满足**最优子结构 + 重叠子问题**，属于动态规划范畴：定义 `dp[k][i][j]` = 只用前 k 个点做中转点时 i 到 j 的最短距离，转移方程只有一行：
    
    ```
    dp[k][i][j] = min( dp[k-1][i][j],  dp[k-1][i][k] + dp[k-1][k][j] )
    ```
    
- **降维**的合法性不是想当然的：因为第 k 行、第 k 列在第 k 轮更新中恒定不变（一个点到自身的最短距离恒为 0），所以可以放心地在同一块二维数组上原地更新，空间从 O(n³) 降到 O(n²)。
- 代码实现上更进一步：`dist` 矩阵**在跑算法前就是邻接矩阵**，跑完后原地变成最短距离矩阵，图存储和 dp 数组共用同一块内存，把"降维"贯彻到了空间复用的极致。

### 📌 推导方法论（可复用到其它DP问题）

这次的推导流程本身也值得沉淀成一套通用套路，以后遇到新的DP问题可以照搬：

1. 🔎 **判断问题类型**：有没有最优子结构 + 重叠子问题？
2. 📦 **定义状态数组**：想清楚初始状态、中间状态、最终状态分别是什么；
3. 🔀 **推导状态转移方程**：新增的那一维"用 or 不用"，取更优的一个；
4. 💻 **写出朴素代码**：先保证正确，不管空间效率；
5. 🗜️ **考虑降维优化**：如果新一维只依赖"上一维"，尝试压缩，但**必须证明原地更新不会读到错误的中间状态**，不能凭直觉。
