### 📌 核心概念总览

最小生成树（Minimum Spanning Tree, MST）是**带权无向连通图**中，边权和最小的生成树。

- 🔹 生成树：包含图中所有 n 个顶点，且恰好有 n-1 条边的极小连通子图
- 🔹 最小生成树：所有生成树中，边权总和最小的那一棵

## 🌳 一、生成树基础概念（必考）

### 🖼️ 生成树示例图

以下内容展示了图 G 及其 3 种不同的生成树：

![Kruskal 2.png](<../pict/Kruskal 2.png>)

- 上方是**原图 G**：3 个顶点（A/B/C），3 条边
- 下方是 3 种合法生成树：每种都包含全部 3 个顶点，且恰好有 2 条边（3-1=2），无环且连通

### 🔹 生成树 7 大核心性质

1. **极小连通性**：生成树是包含全部顶点的最小连通子图，任意去掉一条边都会变成非连通图
2. **边数固定**：n 个顶点的生成树，一定恰好有 **n-1 条边**（n 个点连通的最少边数）
3. **无环性**：生成树中绝对不存在环，任意添加一条边都会形成唯一的环
4. **不唯一性**：一个图的生成树通常不唯一（除非图本身就是树）
5. **凯莱公式**：n 个顶点的无向完全图，生成树的个数为 nn−2
6. **非连通图无生成树**：只有连通图才有生成树，非连通图只有生成森林
7. **最小生成树不唯一性**：当图中存在权值相等的边时，最小生成树可能不唯一，但**总权值一定唯一**

## 💡 二、Kruskal 算法核心思想

### ✨ 算法本质：贪心 + 并查集

Kruskal 算法是**边贪心**算法，核心逻辑只有两步：

1. **贪心选边**：将所有边按权值**从小到大**排序，每次选当前权值最小的边
2. **判环去边**：如果这条边连接的两个顶点**不在同一个连通分量**中，就把它加入最小生成树；否则跳过（会形成环）

### 🔑 核心工具：并查集

并查集是 Kruskal 算法的灵魂，专门解决两个问题：

- ✅ 判断两个顶点是否连通（判环）
- ✅ 合并两个连通分量

## ❓ 三、为什么 Kruskal 必须用边集数组存图？

Kruskal 算法是**唯一以边为核心操作**的图算法，其他存储结构都不适合：

![Kruskal 1.png](<../pict/Kruskal 1.png>)

### 🎯 边集数组的独家优势

1. **天然匹配 Kruskal 需求**：直接存储所有边，不需要额外提取
2. **排序极其方便**：只需要对边数组调用一次 sort 即可
3. **空间利用率最高**：只存实际存在的边，空间复杂度O(e)
4. **实现最简单**：不需要指针、链表，只用一个 vector 存边即可

> 💡 408 考点：Kruskal 算法的存储结构只能是**边集数组**，Prim 算法用邻接矩阵 / 邻接表

## 四、📝 Kruskal 算法完整执行步骤

### 🔧 初始化阶段

- 📦 **存储初始化**：用边集数组完整存储图中所有边，每条边记录两个端点编号与对应权值
- 🔗 **并查集初始化**：每个顶点独立成为一个连通分量，父节点指向自身，秩 / 大小初始化为 1
- 📊 **结果初始化**：MST 边集合置空，总权值初始化为 0

### 🔄 边排序阶段

- 🎯 **核心操作**：将所有边按照权值从小到大进行升序排序
- 💡 **设计原理**：贪心算法的核心基础 —— 每次优先选择权值最小的候选边，通过局部最优选择推导出全局最优解
- ⏱️ **时间开销**：排序是 Kruskal 算法的主要时间瓶颈，对应时间复杂度为 O(eloge)

### 🎯 贪心选边与合并阶段

- 📜 **遍历规则**：按权值从小到大依次遍历每一条边
- 🔍 **判环逻辑**：通过并查集查询边的两个顶点是否属于同一个连通分量
    
    - ✅ **若不连通**：说明这条边不会形成环，将其加入 MST 边集合，累加边权到总权值中，同时用并查集合并两个顶点所在的连通分量
    - ❌ **若连通**：说明加入这条边会形成环，不符合生成树要求，直接跳过
    
- ⚡ **优化技巧**：提前终止 —— 当选中的边数达到 n-1 条时，直接停止遍历，无需处理剩余的边

### ✅ 终止与结果校验

- ✔️ **正常终止**：成功选出 n-1 条边，所有顶点处于同一个连通分量中，得到合法的最小生成树，返回总权值
- ❌ **异常情况**：遍历完所有边后选中的边数仍不足 n-1，说明原图本身不连通，不存在覆盖全顶点的生成树

## 五、🧑‍💻 Kruskal 算法完整代码实现（分模块展示）

### 边集数组存图（Graph 类）

```cpp
/**
 * @brief 无向加权图数据类（边集数组实现）
 * @details 单一职责：仅负责图数据的存储与基本操作，不包含任何算法逻辑
 *          所有数据成员私有，仅通过公共接口访问，保证数据一致性
 */
class Graph {
public:
    /**
     * @brief 图的边结构体（边集数组的基本单元）
     * @details 仅包含边的基本属性与必要的运算符重载，成员变量私有
     *          外部仅能通过只读 getter 方法访问边数据，无法修改
     */
    struct Edge {
        /**
         * @brief 🏗️ 边结构体构造函数
         * @param u_ 边的第一个顶点编号
         * @param v_ 边的第二个顶点编号
         * @param weight_ 边的权值
         */
        Edge(int u_, int v_, int weight_) noexcept
            : u_(u_), v_(v_), weight_(weight_) {
        }

        /// 📍 获取边的第一个顶点编号
        int GetU() const noexcept { return u_; }
        /// 📍 获取边的第二个顶点编号
        int GetV() const noexcept { return v_; }
        /// ⚖️ 获取边的权值
        int GetWeight() const noexcept { return weight_; }

        /**
         * @brief 🔼 小于运算符重载，用于按权值从小到大排序
         * @param other 待比较的另一条边
         * @return 若当前边权值小于 other 则返回 true，否则返回 false
         */
        bool operator<(const Edge& other) const noexcept {
            return weight_ < other.weight_;
        }

    private:
        int u_;      ///< 边的第一个顶点编号
        int v_;      ///< 边的第二个顶点编号
        int weight_; ///< 边的权值
    };

    /// 🏗️ 构造函数：初始化指定顶点数的空图
    explicit Graph(int n);
    /// 🗑️ 析构函数：无动态分配内存，使用默认析构函数即可
    ~Graph() noexcept = default;

    /// 🚫 禁用拷贝构造函数，避免浅拷贝风险
    Graph(const Graph&) = delete;
    /// 🚫 禁用拷贝赋值运算符，避免浅拷贝风险
    Graph& operator=(const Graph&) = delete;

    /// ➕ 向图中添加一条无向加权边
    void AddEdge(int u, int v, int weight);
    /// 🔨 从标准输入批量读取边，构建完整图
    void BuildGraph(int edge_cnt);

    /// 📊 获取图的顶点总数
    int GetVertexCount() const noexcept;
    /// 📦 获取图中所有边的只读引用
    const std::vector<Edge>& GetEdges() const noexcept;

private:
    /// 🔧 批量建图的内部辅助函数：实际执行边输入逻辑
    void BuildGraphHelper(int edge_cnt);

    int vertex_count_;      ///< 图的顶点总数
    std::vector<Edge> edges_; ///< 📦 边集数组核心：存储图中所有边
};

// ====================== Graph 类实现 ======================
Graph::Graph(int n)
    : vertex_count_(n), edges_() {
    if (n <= 0) {
        throw std::invalid_argument("Invalid vertex count (must be a positive integer).");
    }
}

void Graph::AddEdge(int u, int v, int weight) {
    // ✅ 顶点编号合法性校验
    if (u < 1 || u > vertex_count_ || v < 1 || v > vertex_count_) {
        throw std::invalid_argument(std::format(
            "AddEdge failed: vertex {} or {} is out of range [1, {}].",
            u, v, vertex_count_
        ));
    }
    edges_.emplace_back(u, v, weight);
}

void Graph::BuildGraph(int edge_cnt) {
    if (edge_cnt <= 0) {
        throw std::invalid_argument("Invalid edge count (must be a positive integer).");
    }
    edges_.clear();
    BuildGraphHelper(edge_cnt);
}

void Graph::BuildGraphHelper(int edge_cnt) {
    std::cout << "Enter " << edge_cnt << " edges (format: u v weight):" << std::endl;
    for (int i = 0; i < edge_cnt; ++i) {
        int u, v, weight;
        if (!(std::cin >> u >> v >> weight)) {
            throw std::invalid_argument("Invalid edge format. Expected: u v weight.");
        }
        AddEdge(u, v, weight);
    }
}

int Graph::GetVertexCount() const noexcept {
    return vertex_count_;
}

const std::vector<Graph::Edge>& Graph::GetEdges() const noexcept {
    return edges_;
}
```

```cpp
/**
 * @brief Kruskal 最小生成树算法实现类
 * @details 单一职责：仅负责 Kruskal 算法的计算与结果输出
 *          不存储图的原始数据，仅接收 Graph 对象作为输入

class Kruskal {
public:
    /// 🏗️ 默认构造函数
    Kruskal() noexcept;
    /// 🗑️ 析构函数：释放并查集占用的动态内存
    ~Kruskal() noexcept;

    /// 🚫 禁用拷贝构造函数，避免浅拷贝重复释放

    /// 🖨️ 打印最小生成树的结果
    void PrintMST() const;

private:
    /// ⚡ Kruskal算法核心实现：排序、选边、合并集合

    /// 🖨️ 打印最小生成树的辅助函数
```

```cpp
// ====================== Kruskal 公有接口实现 ======================
void Kruskal::ComputeMST(const Graph& graph) {
    // 🔄 重置算法状态，支持多次计算不同的图
    mst_edges_.clear();
    total_weight_ = 0;
    if (uf_ != nullptr) {
        delete uf_;
        uf_ = nullptr;
    }

    // ✅ 前置校验：图不能为空
    if (graph.GetEdges().empty()) {
        throw std::runtime_error("ComputeMST failed: graph has no edges.");
    }

    // 🔗 初始化并查集，大小与图的顶点数一致
    uf_ = new UnionFind(graph.GetVertexCount());

    // 🚀 执行核心算法
    ComputeHelper(graph);

    // ✅ 结果校验：最小生成树必须包含 n-1 条边
    if (mst_edges_.size() != static_cast<size_t>(graph.GetVertexCount() - 1)) {
        throw std::runtime_error("ComputeMST failed: graph is disconnected, cannot form MST.");
    }
}

void Kruskal::PrintMST() const {
    if (mst_edges_.empty()) {
        throw std::runtime_error("PrintMST failed: MST has not been computed yet.");
    }

    std::cout << "\n=== Minimum Spanning Tree (Kruskal Algorithm) ===" << std::endl;
    PrintHelper();
    std::cout << std::format("\nTotal weight of MST: {}", total_weight_) << std::endl;
}
```

### ⚡ 模块 4：核心算法实现

```cpp
// ====================== Kruskal 核心算法实现 ======================
void Kruskal::ComputeHelper(const Graph& graph) noexcept {
    // 📌 第一步：拷贝所有边并按权值从小到大升序排序
    std::vector<Graph::Edge> sorted_edges = graph.GetEdges();
    std::sort(sorted_edges.begin(), sorted_edges.end());

    // 📌 第二步：贪心遍历排序后的边，逐步构建最小生成树
    const int required_edges = graph.GetVertexCount() - 1;
    for (const auto& edge : sorted_edges) {
        // ⏹️ 提前终止优化：已选够 n-1 条边，剩余边无需遍历
        if (mst_edges_.size() == static_cast<size_t>(required_edges)) {
            break;
        }

        const int u = edge.GetU();
        const int v = edge.GetV();
        const int weight = edge.GetWeight();

        // 📌 第三步：并查集判环：两点不连通则加入MST，合并集合
        // 若两点已连通，加入该边会形成环，直接跳过
        if (!uf_->IsConnected(u, v)) {
            uf_->Union(u, v);
            mst_edges_.push_back(edge);
            total_weight_ += weight;
        }
    }
}
```

## ⏱️ 六、时间与空间复杂度分析

### 时间复杂度

- 边排序：O(eloge)（Kruskal 算法的主要时间开销）
- 并查集操作：O(eα(n))（α(n)是阿克曼反函数，近似常数）
- 总时间复杂度：O(eloge)，**与顶点数 n 无关**，仅与边数 e 有关

### 空间复杂度

- 边集数组：O(e)
- 并查集：O(n)
- 总空间复杂度：O(n+e)

> 💡 结论：Kruskal 算法复杂度取决于所使用的排序算法，因此**特别适合稀疏图**（e 远小于 n²），稠密图用 Prim 算法更优

## 🎓 七、408 必考考点速记

1. **存储结构**：Kruskal 算法只能用**边集数组**
2. **核心工具**：并查集（判环 + 合并）
3. **时间复杂度**：O(eloge)，与顶点数无关
4. **适用场景**：稀疏图、边数较少的图
5. **最小生成树性质**：总权值唯一，边的选择可能不唯一
6. **边数性质**：最小生成树一定恰好有 n-1 条边，无环

## ⚠️ 八、常见避坑技巧

1. ❌ 边排序时从大到小排：会得到最大生成树，不是最小生成树
2. ❌ 忘记提前终止：选够 n-1 条边后无需继续遍历，浪费时间
3. ❌ 并查集没有优化：会导致时间复杂度退化为O(en)
4. ❌ 顶点编号不统一：代码中用 1-based 编号，输入时要对应
5. ❌ 不判断图是否连通：非连通图没有最小生成树，会抛出异常
