### 📌 图的存储本质

图是**多对多**的网状结构，内存是线性的，所以我们必须想办法把 "网状关系" 转成 "线性存储"。所有图存储结构都只解决两个问题：

1. 📍 怎么存**顶点**（比如 A、B、C、D 这些节点）
2. 🔗 怎么存**边**（顶点之间的连接关系，比如 A 到 B 有没有边，权值是多少）

408 考纲要求掌握的 5 种存储：

- ✅ 通用存储：边集数组、邻接矩阵、邻接表
- ✅ 专用存储：十字链表（只存**有向图**）、多重邻接表（只存**无向图**）

---

### 🔍 先搞懂一个核心符号：d(v)

#### ✅ 定义

$d(v)$ 表示**顶点 v 的度（Degree）**，也就是与顶点 v 直接相连的边的数量。

- 🟢 无向图：$d(v)$ 就是顶点 v 连了多少条边
- 🔵 有向图：
    
    - 出度 $d^+(v)$：从 v 出发的边的数量
    - 入度 $d^−(v)$：指向 v 的边的数量
    - 总度 $d(v)=d^+(v)+d^−(v)$
    

#### ✅ 为什么这个符号这么重要？

它直接决定了**邻接表、十字链表、多重邻接表**的时间复杂度！

- 想查 "v 和 u 之间有没有边"：需要遍历 v 的所有邻接点，最多遍历 $d(v)$ 个节点，所以时间复杂度是 $O(d(v))$
- 想求 v 的度数：需要遍历 v 的所有邻接点，时间复杂度也是 $O(d(v))$

#### ✅ 平均情况分析

- 稀疏图：边数 $e≪n^2$，平均每个顶点的度 $dˉ(v)=\frac{2e}{n}≪n$，所以 $O(d(v))$ 近似于 $O(1)$，非常快
- 稠密图：边数 $e≈n^2$，平均每个顶点的度 %dˉ(v)≈n%，所以 $O(d(v))$ 近似于 $O(n)$，和邻接矩阵一样慢

> 💡 这就是为什么**稀疏图用邻接表，稠密图用邻接矩阵**的根本原因！

## 1. 📦 边集数组（最简单的存储）

### ✨ 核心思想

用两个一维数组搞定：

- 顶点数组：按顺序存所有顶点的名字
- 边数组：每个元素存一条边的**起点下标、终点下标、权值**

### 📝 结构示例

```cpp
顶点数组：vertex[] = {A, B, C, D}  // 下标0:A, 1:B, 2:C, 3:D
边数组：edge[] = {
    {0, 1, 3},  // 第0条边：A(0) → B(1)，权值3
    {0, 3, 6},  // 第1条边：A(0) → D(3)，权值6
    {1, 2, 0}   // 第2条边：B(1) → C(2)，权值0
}
```

### 🛠️ 基本操作时间复杂度

- 插入边：$O(1)$（直接加到边数组末尾）
- 删除边：$O(e)$（需要遍历边数组找到要删的边）
- 查询边：$O(e)$（需要遍历所有边）
- 求顶点 v 的度：$O(e)$（需要遍历所有边统计和 v 相关的）

### ✅ 优点

- 结构超级简单，写代码最快
- 特别适合**只需要处理边**的算法（比如 Kruskal 最小生成树）

### ❌ 缺点

- 所有和顶点相关的操作都很慢，因为都要遍历整个边数组
- 完全不适合需要频繁查询顶点邻接点的场景

### 🎯 适用场景

- 边很少的稀疏图
- Kruskal 算法专用（只需要对边排序，不需要查顶点邻接点）

## 2. 🧮 邻接矩阵（最直观的存储）

### ✨ 核心思想

用**二维表格**存边！行是起点，列是终点，表格里的值就是边权。

- 比如`matrix[i][j] = 5`，表示顶点 i 到顶点 j 有一条权值为 5 的边
- 如果`matrix[i][j] = INF`（无穷大），表示 i 和 j 之间没有边

### 📊 存储规则

| 图类型    | 有边   | 无边    | 特殊性质                               |
| :----- | :--- | :---- | :--------------------------------- |
| 无向无权图  | 1    | 0     | 对称矩阵！`matrix[i][j] = matrix[j][i]` |
| 有向无权图  | 1    | 0     | 不对称                                |
| 带权图（网） | 权值 w | $INF$ | 无向图依然对称                            |

### 💡 关键性质（408 必考）

- 无向图顶点 i 的度数 $d(i)$ = 第 i 行所有非 INF 元素的个数 = 第 i 列所有非 INF 元素的个数
- 有向图顶点 i 的**出度** $d+(i)$ = 第 i 行非 INF 元素的个数
- 有向图顶点 i 的**入度** $d−(i)$ = 第 i 列非 INF 元素的个数
- 无向图邻接矩阵的所有元素之和 = $2e$（握手定理）
- 有向图邻接矩阵的所有元素之和 = $e$

### 🛠️ 基本操作时间复杂度

- 插入边：$O(1)$（直接给`matrix[i][j]`赋值）
- 删除边：$O(1)$（直接把`matrix[i][j]`设为 $INF$）
- 查询边：$O(1)$（直接看`matrix[i][j]`是不是 $INF$）
- 求顶点 v 的度：$O(n)$（需要遍历一行或一列）

### 🧑‍💻 核心代码（只保留特有部分）

```cpp
namespace adjacency_matrix {
    class AM {
    private:
        char* vertex_list_;       // 顶点数组：存所有顶点的名字
        int** matrix_;            // 邻接矩阵二维数组：matrix[i][j]存i到j的边权
        int vertex_count_;        // 顶点总数n
        int edge_count_;          // 边总数e
        static constexpr int INF_ = INT_MAX;  // 无穷大，代表两个顶点之间没有边

    public:
        AM() noexcept;
        ~AM() noexcept;  // 内存释放：先释放每一行的数组，再释放矩阵的行指针数组
        AM(const AM&) = delete;
        AM& operator=(const AM&) = delete;

        // 👇 以下函数所有存储结构通用，逻辑完全一致
        void BuildGraph(int vertex_cnt, int edge_cnt, const char vertexs[]);
        void Insert(char vertex_a, char vertex_b, int weight);
        int Find(char vertex) const;  // 遍历顶点数组，返回顶点对应的下标
        int GetDegree(char vertex) const;

    private:
        // 🔥 邻接矩阵特有：无向图双向赋值
        void InsertHelper(int va_id, int vb_id, int weight) {
            // 无向边等价于两条方向相反的有向边，所以两个位置都要赋值
            matrix_[va_id][vb_id] = weight;
            matrix_[vb_id][va_id] = weight;
        }

        // 🔥 邻接矩阵特有：统计一行非INF元素的个数
        int GetDegreeHelper(int v_id) const noexcept {
            int cnt = 0;
            // 遍历第v_id行，统计所有不是INF的元素，就是顶点v_id的度数
            for (int i = 0; i < vertex_count_; i++) {
                if (matrix_[v_id][i] != INF_) cnt++;
            }
            return cnt;
        }
    };

    void runTest(); // 测试函数省略
}
```

### ✅ 优点

- 查边超快！$O(1)$ 就能知道任意两个点之间有没有边
- 求度数超方便，直接数行 / 列就行
- 实现简单，逻辑最直观

### ❌ 缺点

- 空间浪费巨大！空间复杂度 $O(n^2)$
    
    - 举个例子：1000 个顶点的图，邻接矩阵需要开 1000×1000=100 万个 int，占 4MB 内存
    - 如果这个图只有 1000 条边（稀疏图），那么 99.9% 的空间都是 $INF$，纯浪费
    
- 插入和删除顶点非常麻烦，需要重新分配整个矩阵

### 🎯 适用场景

- 顶点数少的**稠密图**（边很多，接近完全图）
- 需要频繁查询边是否存在的场景
- Floyd 多源最短路径算法专用（需要频繁访问任意两个顶点之间的边权）

## 3. 🔗 邻接表（最常用的存储）

### ✨ 核心思想

**数组 + 链表**的组合！完美解决邻接矩阵空间浪费的问题：

- 顶点数组：每个元素是一个链表的头节点
- 每个顶点后面挂一个单链表，链表中存它所有的**邻接点**和对应的边权

### 📊 存储规则

- 无向图：每条边存两次！比如 A-B 这条边，A 的链表存 B，B 的链表存 A
- 有向图：邻接表只存**出边**（方便求得出度），如果要求入度，得再建一个 "逆邻接表" 存入边

### 💡 为什么这是最常用的存储？

因为 99% 的图算法（DFS、BFS、Dijkstra、Prim）都只需要**遍历一个顶点的所有邻接点**，邻接表正好完美支持这个操作！而且空间利用率极高。

### 🛠️ 基本操作时间复杂度

- 插入边：$O(1)$（头插法，直接插到链表头部）
- 删除边：$O(d(v))$（需要遍历 v 的链表找到要删的边）
- 查询边：$O(d(v))$（需要遍历 v 的链表看有没有 u）
- 求顶点 v 的度：$O(d(v))$（需要遍历 v 的链表统计节点数）

### 🧑‍💻 核心代码（只保留特有部分）

```cpp
namespace adjacency_list {
    class AL {
    private:
        // 边节点：存邻接点的下标和边权
        struct Node {
            int id;         // 邻接点在顶点数组中的下标
            int weight;     // 这条边的权值
            Node* next;     // 指向下一个边节点的指针
        };

        // 顶点节点：存顶点数据和链表头指针
        struct Graph {
            char data;      // 顶点的名字（比如'A'、'B'）
            Node* first;    // 指向该顶点的第一条边节点
        };

        Graph* vertex_list_;    // 顶点数组：每个元素是一个链表头
        int vertex_count_;      // 顶点总数n
        int edge_count_;        // 边总数e

    public:
        AL() noexcept;
        ~AL() noexcept;  // 内存释放：遍历每个顶点，释放它的所有边节点
        AL(const AL&) = delete;
        AL& operator=(const AL&) = delete;

        // 👇 以下函数所有存储结构通用，逻辑完全一致
        void BuildGraph(int vertex_cnt, int edge_cnt, const char vertexs[]);
        void Insert(char vertex_a, char vertex_b, int weight);
        int Find(char vertex) const;
        int GetDegree(char vertex) const;

    private:
        // 🔥 邻接表特有：无向图双向头插
        void InsertHelper(int va_id, int vb_id, int weight) {
            // 第一步：在顶点va_id的链表头插入边节点，指向vb_id
            Node* p = new Node{vb_id, weight, vertex_list_[va_id].first};
            vertex_list_[va_id].first = p;

            // 第二步：在顶点vb_id的链表头插入边节点，指向va_id（无向图双向特性）
            p = new Node{va_id, weight, vertex_list_[vb_id].first};
            vertex_list_[vb_id].first = p;
        }

        // 🔥 邻接表特有：统计链表节点的个数
        int GetDegreeHelper(int v_id) const noexcept {
            int cnt = 0;
            Node* p = vertex_list_[v_id].first;
            // 遍历整个链表，节点个数就是顶点v_id的度数
            while (p) {
                cnt++;
                p = p->next;
            }
            return cnt;
        }
    };

    void runTest(); // 测试函数省略
}
```

### ✅ 优点

- 空间利用率超高！空间复杂度 $O(n+e)$
    
    - 还是刚才的例子：1000 个顶点 1000 条边的无向图，邻接表只需要 1000 个顶点节点 + 2000 个边节点，占约 24KB 内存，比邻接矩阵省 160 倍！
    
- 插入边超快！$O(1)$ 头插法
- 遍历一个顶点的所有邻接点超快，正好是图算法最常用的操作

### ❌ 缺点

- 查边慢！想知道 A 和 B 有没有边，得遍历 A 的整个链表
- 无向图每条边存两次，有点冗余
- 有向图求入度麻烦，得额外建一个逆邻接表

### 🎯 适用场景

- 顶点多的**稀疏图**（99% 的实际场景都是稀疏图）
- DFS、BFS、Dijkstra、Prim 等绝大多数图算法专用

## 4. ➕ 十字链表（有向图专用）

### ✨ 核心思想

解决**有向图邻接表求入度麻烦**的问题！把邻接表和逆邻接表合二为一：

- 每个顶点维护两个链表：**出边链表**（存从它出发的边）和**入边链表**（存指向它的边）
- 每条边只用**一个节点**存，同时挂在起点的出边表和终点的入边表

### 📝 边节点结构（5 个字段，教材标准）

|字段|含义|
|:--|:--|
|`tail_`|弧尾（起点）在顶点数组中的下标|
|`head_`|弧头（终点）在顶点数组中的下标|
|`weight_`|这条有向边的权值|
|`tail_next_`|指向**同起点**的下一条出边|
|`head_next_`|指向**同终点**的下一条入边|

### 💡 为什么叫 "十字"？

因为一个边节点同时属于两个链表，就像十字路口一样，从起点的出边表能找到它，从终点的入边表也能找到它！

### 🛠️ 基本操作时间复杂度

- 插入边：$O(1)$（头插法，同时挂两个链表）
- 删除边：$O(d(v))$（需要遍历起点的出边表找到要删的边）
- 查询边：$O(d^+(v))$（遍历起点的出边表）
- 求顶点 v 的出度：$O(d^+(v))$（遍历出边表）
- 求顶点 v 的入度：$O(d^−(v))$（遍历入边表）

### 🧑‍💻 核心代码（只保留特有部分）

```cpp
namespace orthogonal_linked_list {
    class OrthList {
    private:
        // 度数类型枚举：区分入度和出度
        enum class DegreeType { IN_DEGREE, OUT_DEGREE };

        // 🔥 十字链表特有边节点结构
        struct Node {
            int weight_;
            int tail_;    // 弧尾（起点）下标
            int head_;    // 弧头（终点）下标
            Node* tail_next_;  // 同起点的下一条出边
            Node* head_next_;  // 同终点的下一条入边
        };

        // 🔥 十字链表特有顶点节点：两个链表头
        struct Graph {
            char data_;
            Node* first_in_;   // 入边链表头指针
            Node* first_out_;  // 出边链表头指针
        };

        Graph* vertex_list_;
        int vertex_count_;
        int edge_count_;

    public:
        OrthList() noexcept;
        ~OrthList() noexcept;  // 只遍历出边表释放边节点，避免重复释放
        OrthList(const OrthList&) = delete;
        OrthList& operator=(const OrthList&) = delete;

        // 👇 以下函数所有存储结构通用，逻辑完全一致
        void BuildGraph(int vertex_cnt, int edge_cnt, const char vertexs[]);
        void Insert(char vertex_tail, char vertex_head, int weight);
        int Find(char vertex) const;
        int GetInDegree(char vertex) const;
        int GetOutDegree(char vertex) const;

    private:
        // 🔥 十字链表核心插入：一个节点同时挂两个链表
        void InsertHelper(int tail_id, int head_id, int weight) {
            Node* p = new Node{weight, tail_id, head_id, nullptr, nullptr};
            
            // 第一步：把边节点挂到起点的出边链表头部
            p->tail_next_ = vertex_list_[tail_id].first_out_;
            vertex_list_[tail_id].first_out_ = p;

            // 第二步：把同一个边节点挂到终点的入边链表头部
            p->head_next_ = vertex_list_[head_id].first_in_;
            vertex_list_[head_id].first_in_ = p;
        }

        // 🔥 十字链表特有：根据度数类型遍历不同的链表
        int GetDegreeHelper(int v_id, DegreeType type) const noexcept {
            int cnt = 0;
            Node* p = nullptr;
            if (type == DegreeType::IN_DEGREE) {
                // 求入度：遍历入边链表
                p = vertex_list_[v_id].first_in_;
                while (p) { cnt++; p = p->head_next_; }
            } else {
                // 求出度：遍历出边链表
                p = vertex_list_[v_id].first_out_;
                while (p) { cnt++; p = p->tail_next_; }
            }
            return cnt;
        }
    };

    void runTest(); // 测试函数省略
}
```

### ✅ 优点

- 同时支持入度和出度查询，不用建两个表
- 每条边只存一次，比有向图邻接表省一半空间
- 可以快速找到所有以某个点为起点 / 终点的边

### ❌ 缺点

- 结构复杂，写代码容易错
- 插入删除边的逻辑有点绕

### 🎯 适用场景

- 需要频繁操作有向图入边和出边的场景
- 拓扑排序、关键路径等有向图算法

## 5. 🔄 多重邻接表（无向图专用）

### ✨ 核心思想

解决**无向图邻接表边重复存储**的问题！

- 无向图邻接表每条边存两次，浪费空间还不好删边
- 多重邻接表每条边只用**一个节点**存，同时挂在两个顶点的链表中

### 📝 边节点结构（5 个字段，教材标准）

|字段|含义|
|:--|:--|
|`a_`|边的第一个顶点在顶点数组中的下标|
|`b_`|边的第二个顶点在顶点数组中的下标|
|`weight_`|这条无向边的权值|
|`a_next_`|指向顶点 a_的下一条邻接边|
|`b_next_`|指向顶点 b_的下一条邻接边|

### 💡 怎么遍历顶点 v 的所有边？

遍历的时候需要判断当前顶点是边的 a 还是 b：

- 如果`p->a_ == v`，说明 v 是这条边的 a，下一条边走`p->a_next_`
- 如果`p->b_ == v`，说明 v 是这条边的 b，下一条边走`p->b_next_`

### 🛠️ 基本操作时间复杂度

- 插入边：$O(1)$（头插法，同时挂两个链表）
- 删除边：$O(d(v))$（只需要找到一个边节点删掉就行，不用删两个）
- 查询边：$O(d(v))$（遍历 v 的链表）
- 求顶点 v 的度：$O(d(v))$（遍历 v 的链表）

### 🧑‍💻 核心代码（只保留特有部分）

```cpp
namespace multi_adjacency_list {
    class MAL {
    private:
        // 🔥 多重邻接表特有边节点结构
        struct Node {
            int weight_;
            int a_;    // 顶点1下标
            int b_;    // 顶点2下标
            Node* a_next_;  // 顶点1的下一条边
            Node* b_next_;  // 顶点2的下一条边
        };

        // 顶点节点：一个链表头
        struct Graph {
            char data_;
            Node* first_;  // 邻接边链表头指针
        };

        Graph* vertex_list_;
        int vertex_count_;
        int edge_count_;

    public:
        MAL() noexcept;
        ~MAL() noexcept;  // 用哈希集合记录已释放节点，避免重复释放
        MAL(const MAL&) = delete;
        MAL& operator=(const MAL&) = delete;

        // 👇 以下函数所有存储结构通用，逻辑完全一致
        void BuildGraph(int vertex_cnt, int edge_cnt, const char vertexs[]);
        void Insert(char vertex_a, char vertex_b, int weight);
        int Find(char vertex) const;
        int GetDegree(char vertex) const;

    private:
        // 🔥 多重邻接表核心插入：一个节点同时挂两个链表
        void InsertHelper(int va_id, int vb_id, int weight) {
            Node* p = new Node{weight, va_id, vb_id, nullptr, nullptr};
            
            // 第一步：把边节点挂到顶点va_id的链表头部
            p->a_next_ = vertex_list_[va_id].first_;
            vertex_list_[va_id].first_ = p;

            // 第二步：把同一个边节点挂到顶点vb_id的链表头部
            p->b_next_ = vertex_list_[vb_id].first_;
            vertex_list_[vb_id].first_ = p;
        }

        // 🔥 多重邻接表特有：判断当前顶点是a还是b，选择对应指针
        int GetDegreeHelper(int v_id) const noexcept {
            int cnt = 0;
            Node* p = vertex_list_[v_id].first_;
            while (p) {
                cnt++;
                // 根据当前顶点是a还是b，选择下一个指针
                p = (p->a_ == v_id) ? p->a_next_ : p->b_next_;
            }
            return cnt;
        }
    };

    void runTest(); // 测试函数省略
}
```

### ✅ 优点

- 空间利用率最高！无向图每条边只存一次，比邻接表省一半空间
- 删边超方便！找到那个边节点删掉就行，不用删两个
- 适合对边进行标记、删除等操作

### ❌ 缺点

- 结构最复杂，写代码最容易错
- 遍历的时候要判断是 a 还是 b，逻辑有点绕

### 🎯 适用场景

- 无向图中需要频繁删边、标记边的场景
- 空间特别紧张的无向图应用

## 🔍 深度对比：十字链表 vs 多重邻接表 —— 同源的两种优化分支

### 🧬 本质同源：邻接表思想的延伸

二者属于**同根同源的链式优化结构**，底层逻辑完全继承自邻接表：

- 存储形态一致：顶点用顺序数组存储，每条边是独立的堆节点，通过指针串联成链表；整个结构除顶点数组外，没有其他连续的顺序存储空间。
- 设计目标一致：在不牺牲邻接表遍历效率的前提下，解决原生邻接表的**冗余存储痛点**。
- 核心技巧一致：每条边仅用一个节点存储，同时挂载到两个关联顶点的链表中，用双指针实现「一边两挂」。

### 🎯 设计初衷的分野：针对两类图的不同痛点

二者从设计之初就分别瞄准了有向图、无向图各自的缺陷，这也是它们适用范围严格区分的根本原因。

![图的存储 2.png](<../pict/图的存储 2.png>)

> 💡 补充：顶点节点、边节点的字段都是为对应场景量身定做的，结构本身就自带图类型属性，无法通用。

### 🏗️ 结构底层差异

#### 1. 顶点节点的字段差异

- ➕ 十字链表：每个顶点维护 **2 个头指针**
    
    - `first_out`：出边链表头，指向所有从该顶点出发的边
    - `first_in`：入边链表头，指向所有指向该顶点的边
    - 完美对应有向图「入度、出度」的二元属性
    
- 🔄 多重邻接表：每个顶点只维护 **1 个头指针** `first`
    
    - 无向图没有入度出度的区分，所有邻接边共用同一条链表
    

#### 2. 边节点的设计差异

- ➕ 十字链表边节点：语义明确固定，方向感强
    
    - `tail` / `head`：严格区分弧尾（起点）、弧头（终点），有向边方向固定
    - `tail_next`：串联同起点的所有出边
    - `head_next`：串联同终点的所有入边
    - 一条边节点同时挂在起点的出边表、终点的入边表上
    
- 🔄 多重邻接表边节点：地位完全对等，无方向
    
    - `a` / `b`：仅表示边的两个端点，无先后顺序，地位完全平等
    - `a_next`：串联顶点 a 的下一条邻接边
    - `b_next`：串联顶点 b 的下一条邻接边
    - 一条边节点同时挂在两个端点的邻接表上
    

### 🚶 遍历逻辑差异：静态路线 vs 动态决策

这是二者最核心的运行时区别，直接影响代码逻辑和执行效率。

#### ➕ 十字链表：静态路线，出发即确定

- 遍历开始前就已经明确需求：查入度就从 `first_in` 出发，全程沿 `head_next` 前进；查出度就从 `first_out` 出发，全程沿 `tail_next` 前进。
- 遍历过程中**不需要做任何条件判断**，路线是静态固定的，逻辑更规整，执行效率略高。
- 类比：上高速前就选好了车道，一路直行不用变道。

#### 🔄 多重邻接表：动态决策，边走边判断

- 遍历前只有一个统一的起点 `first`，每走到一条边，都要先做一次判断：「当前顶点是这条边的 a 还是 b」：
    
    - 如果是 a，下一步走 `a_next`
    - 如果是 b，下一步走 `b_next`
    
- 遍历过程中**每次循环都要执行一次条件判断**，路线是动态选择的，逻辑稍绕，运行时开销略高一点。
- 类比：走岔路口每次都要先看路牌再选方向。

### 🎓 408 必考考点速记

1. 🧮 稠密图用**邻接矩阵**，稀疏图用**邻接表**（选择题必考）
2. 🔄 无向图邻接矩阵一定是**对称矩阵**
3. ➡️ 有向图邻接表只能求**出度**，求入度要逆邻接表
4. ➕ 十字链表存**有向图**，多重邻接表存**无向图**
5. 📦 Kruskal 算法必须用**边集数组**
6. 📊 d(v)是顶点 v 的度，决定了链式存储结构的时间复杂度

### ⚠️ 避坑提醒

- 邻接矩阵的 INF 要设得比所有可能的边权都大，不然会溢出
- 无向图邻接表的边节点数是实际边数的 2 倍，计算的时候要除以 2
- 十字链表和多重邻接表释放内存时，千万不要重复释放同一个边节点！
- 头插法会导致边的顺序与输入顺序相反，但不影响任何算法的正确性
