### 📌 核心概念：什么是链式队列？

链式队列是**基于带头结点的单链表**实现的队列，彻底解决顺序队列的假溢出、容量固定问题。

- **队首 (Front)**：靠近头结点的一侧，front 指针指向头结点，`front->next` 是真正的队首元素。
- **队尾 (Rear)**：靠近链表尾结点的一侧，rear 指针永远指向链表的最后一个结点，尾插法入队无需遍历找尾。
- **空队列**：front 和 rear 均指向头结点，无数据结点。
- **核心性质**：**先进先出 (FIFO, First In First Out)**，动态内存分配，无固定容量限制。

---

### 🔑 核心设计逻辑

#### 1. 双指针设计

采用`front`（队首指针）+ `rear`（队尾指针）双指针结构，入队、出队操作时间复杂度均为**O(1)**，无需遍历链表。

#### 2. 结构体封装的意义

将两个指针封装进`Queue`结构体，核心优势：

- 若直接使用两个独立的结点指针，修改指针本身需要传递**二级指针**，传参和逻辑复杂；
- 封装后，仅需传递一个`Queue*`结构体指针，即可同时修改两个成员指针，简化逻辑，规避二级指针的使用。

---

### 💡 为什么不把 front/rear 放进 QNode 结构体？

#### 1. QNode 的核心定位

`QNode` 是**纯数据结点**，是单链表的标准原子结构，职责单一：

- 仅需存储当前结点的数据 `data`
- 仅需存储指向下一个结点的指针 `next`
    
    这是链表结点的通用、简洁设计，无需额外冗余字段。

#### 2. 硬塞进去的严重后果

如果强行把 `front` 和 `rear` 塞进 `QNode`，会导致：

- **每个数据结点都变成 “4 指针古怪结点”**：除了 `data` 和 `next`，还多了两个完全无用的 `front`/`rear` 指针，**严重浪费内存**，逻辑也极其混乱。
- **概念完全错位**：`front`/`rear` 是 “管理整个队列的全局工具指针”，不是 “某个数据结点的私有属性”，它们的作用是**指向队列的头尾结点**，而非成为结点的一部分。

#### 3. 正确的设计逻辑

- **`QNode`**：负责 “存数据”，是链表的基本单元
- **`LinkQueue`**：负责 “管队列”，是封装两个全局指针的 “管理包裹”
    
    二者职责分离，逻辑清晰，是链式队列的标准、优雅设计。

# 💻 链式队列核心代码实现

```c
// 链式队列（带头结点单链表实现）
// 核心操作：初始化、入队、出队、查队头、查队尾、判空
namespace Linked_Queue {
	typedef struct Node {
		int data;
		struct Node* next;
	}QNode;

	// 封装队首、队尾指针，简化传参逻辑
	typedef struct LinkQueue {
		QNode* front;	// 队首指针，指向头结点
		QNode* rear;	// 队尾指针，指向最后一个数据结点
	}Queue;

	// 初始化带头结点的空队列
	Queue* initQueue(void)
	{
		// 创建头结点
		QNode* s = (QNode*)malloc(sizeof(QNode));
		s->next = NULL;
		// 创建队列结构体，front、rear均指向头结点
		Queue* p = (Queue*)malloc(sizeof(Queue));
		p->front = p->rear = s;
		return p;
	}

	// 判断队空
	bool isEmpty(Queue* q)
	{
		return q->front == q->rear;
	}

	// 入队操作（尾插法）
	void enqueue(Queue* q, int x)
	{
		// 1. 创建新结点
		QNode* s = (QNode*)malloc(sizeof(QNode));
		s->data = x;
		s->next = NULL;

		// 2. 新结点链接到队尾
		q->rear->next = s;
		// 3. 队尾指针后移
		q->rear = s;
	}

	// 出队操作（删除队首元素）
	void dequeue(Queue* q)
	{
		// 空队列直接返回
		if (isEmpty(q))
		{
			printf("Queue empty, cannot dequeue.\n");
			return;
		}

		// 拿到待删除的队首结点
		QNode* p = q->front->next;

		// 【关键特殊处理】若删除的是最后一个结点，重置rear到头结点，避免野指针
		if (p == q->rear)
			q->rear = q->front;

		// 断链，移除队首结点
		q->front->next = p->next;

		// 释放内存
		free(p);
		p = NULL;
	}

	// 获取队头元素
	void getFront(Queue* q)
	{
		if (!isEmpty(q))
			printf("The front element of the queue is %d.\n", q->front->next->data);
		else
			printf("Queue is empty, no front element.\n");
	}

	// 获取队尾元素
	void getRear(Queue* q)
	{
		if (!isEmpty(q))
			printf("The rear element of the queue is %d.\n", q->rear->data);
		else
			printf("Queue is empty, no rear element.\n");
	}

	// 测试函数
	void runTest(void)
	{
		Queue* q = initQueue();

		enqueue(q, 1);
		enqueue(q, 2);
		//（...内容重复略）
	}
}
```

### ⚠️ 关键细节详解（考研高频考点）

#### 1. 判空逻辑

两种完全等价的判空写法：

- 代码采用：`q->front == q->rear`（最简洁，推荐）
- 等价写法：`q->front->next == NULL`
    
    空队列时，front 和 rear 均指向头结点，头结点的`next`为 NULL，二者逻辑完全一致。

#### 2. 出队的特殊情况（核心重点）

当队列中**只有一个数据结点**时（`p == q->rear`），出队后队列变为空，必须将`rear`指针重置回头结点，否则`rear`会指向已经被 free 的内存，变成**野指针**，导致程序崩溃。这是链式队列最容易出错的点，也是考研选择题、代码题的高频考点。

#### 3. 入队的操作顺序

必须**先链接新结点，再移动 rear 指针**，顺序不能颠倒。若先移动 rear，会导致链表断链，新结点无法正确接入。

#### 4. 判满逻辑

链式队列**无需主动判满**，只有当系统内存不足，`malloc`申请结点失败时，队列才会 “满”，日常使用中无需像顺序队列 / 循环队列一样提前判满。

### ⚖️ 链式队列 vs 循环队列（对比总结）

表格

|特性|链式队列|循环队列|
|:--|:--|:--|
|**存储结构**|带头结点单链表|逻辑循环数组|
|**容量限制**|动态分配，无固定容量|静态分配，容量固定|
|**溢出问题**|无假溢出，仅内存不足时上溢|无假溢出，数组满时上溢|
|**时间复杂度**|入队、出队均为 O (1)|入队、出队均为 O (1)|
|**空间效率**|高，按需分配内存|较高，需提前分配固定大小数组|
|**适用场景**|数据量不确定、频繁增减的场景|数据量固定、对性能要求高的场景|

### 📝 考研经典例题（408 高频考点）

**题目**：在带头结点的链式队列中，队头指针为`front`，队尾指针为`rear`，则执行出队操作时，下列说法正确的是（）

A. 任何情况下，都只需修改`front->next`

B. 当`front->next == rear`时，需先修改`rear`，再修改`front->next`

C. 当`front->next == rear`时，需先修改`front`，再修改`rear`

D. 当`front->next == NULL`时，才需要修改`rear`

**答案**：B

**简要解析**：

1. 普通情况（队列有多个元素）：出队只需修改`front->next = front->next->next`，无需操作`rear`，因此 A 错误；
2. 特殊情况（队列只有 1 个元素）：此时`front->next == rear`，出队后队列变空，必须先将`rear`重置为头结点（与`front`重合），再修改`front->next`，否则`rear`会变成野指针，因此 B 正确，C 逻辑错误；
3. `front->next == NULL`对应空队列，空队列无法执行出队操作，因此 D 错误。

### 📝 笔记重点

1. 核心结构：带头结点单链表 + front/rear 双指针，入队尾插、出队头删，O (1) 时间复杂度。
2. 封装意义：用结构体指针规避二级指针，简化传参和操作逻辑。
3. 易错点：出队最后一个元素时，必须重置 rear 指针到头结点，避免野指针。
4. 判空规则：`front == rear` 为空，无需复杂判断。
5. 无容量限制：动态分配内存，无假溢出问题。
